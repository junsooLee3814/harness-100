## 0. 설계 관통 규약 (모든 실습에 강제 적용)

> **배포 주의 (청킹 보호)**: 본 §0 규약·이월 대장과 문서 말미의 루브릭·운영 노트는 **강사·조교용**이다. 여기에는 4·5강 용어(**에이전트팀·하네스**)가 전체 조망 목적으로 등장한다. **학습자 배포본은 해당 강 실습 절만 발췌해 배포**하고, 1~3강 시점에는 이 두 용어를 노출하지 않는다(3강까지는 개념 5종 — 스킬·MCP·커넥터·에이전트·프로젝트만). 학습자가 먼저 물으면 "다음 강에서 확장한다"로만 답한다.

### 0.1 3대 설계원칙 준수 방식

| 원칙 | 본 실습설계 반영 방식 |

| **⓷ 강사+조교 배석** | 3인 1조 + 강사 1 + 조교 1~2. 각 실습에 **[조교 개입 신호]**를 명시했다. 한 명이 막히면 조 전체가 멈추므로 신호 발생 시 즉시 개입한다. |

### 0.3 3단 힌트 시스템 (전 실습 공통 — 조별 진도 편차 흡수)

막히면 아래 순서로만 개입한다. **정답을 바로 주지 않는다.**

```
[스스로 시도] ── 3분 경과 ──▶
[힌트 1·방향]  "이건 ○○ 개념이에요. 배포자료의 △△ 섹션을 보세요."   ── 3분 ──▶
[힌트 2·접근]  "이 프롬프트/설정을 여기에 붙여 보세요: (일부 공개)"     ── 3분 ──▶
[힌트 3·골격]  "구조는 이래요: (스켈레톤 절반 공개)"                  ── 3분 ──▶
[조교 1:1]    화면 공유로 함께 완성 → 반드시 "왜 이렇게 되는지" 1줄 회고
```

- **빠른 조**: 각 실습의 `[확장 과제]`로 상향(추가 기능·제약 1개).
- **느린 조**: 각 실습의 `[최소 통과선]`만 달성하면 통과(다음 강 진입 자격 확보).

### 0.5 안전 루브릭 (전 실습 공통 게이트, 5항목 — 위반 시 산출물 반려 후 재실행)

점수가 아니라 **게이트**다. 모든 실습 제출 전 자기점검 체크박스로 통과해야 한다.

- [ ] **① 비밀키 노출 0** — `service_role`·API 키·토큰이 코드·화면·스크린샷·프롬프트 어디에도 없다(하드코딩 포함). 공개키 `anon`만 허용.
- [ ] **② 고객/개인정보 프롬프트 입력 0** — 실명·주민번호·계좌·연락처·고객 식별정보를 폼 예시·프롬프트·테스트 데이터에 넣지 않았다. **5강은 본인 업무 데이터 가명화 확인.**
- [ ] **③ 검증 단계 수행** — AI 생성 숫자·법조항·출처를 사람이 확인했다(2강 이후 필수, 4강 검증 에이전트 생략 금지).
- [ ] **④ 데이터 흐름 확인** — Gmail·MCP가 데이터를 **어디로 보내는지** 확인했고, **테스트 발송은 본인 메일로만** 했다.
- [ ] **⑤ 사람 최종 확인** — 대외 산출·사내 공유 저장소 등재 전 비밀키·내부정보 제거를 사람이 최종 확인했다.

## 1강 실습 — "출발선 정렬, 그리고 첫 배포" (블록 1-2 · 1-6 · 1-7)

### 실습 1-A: 설치·계정 완료 확인·보정 — 10종 도구 체크리스트 【블록 1-2 · 40분】
**목표**: (적용) 계정 5종·설치 도구를 체크리스트로 확인하고 미비점을 현장 보정한다. — 1강 종료 시 체크리스트 100%가 2강 이후의 절대 선수조건.
**난이도**: 빈칸 채우기(상태칸만 채움) · **조교 전원 투입 블록**

#### 시나리오
당신은 코딩 무경험 정규직이다. 사전 안내서로 미리 시도해 왔지만 어딘가 막혔을 수 있다. 오늘 이 40분 안에 "연장 10종"을 전부 손에 쥔다. 미완료는 부끄러운 게 아니라 **이 블록의 존재 이유**다 — 손을 들면 조교가 온다.

#### 스타터 (실제 문안 — 배포 워크시트)
```markdown
# 1강 10종 도구 체크리스트  (상태칸·증거칸만 채우세요)
## A. 계정 5종
- [ ] 1. Claude Pro 결제·로그인          증거: 로그인 화면 확인 ____
- [ ] 2. GitHub 가입·로그인              증거: ____
- [ ] 3. Vercel 가입(GitHub 연동 로그인)  증거: ____
- [ ] 4. Supabase 프로젝트 1개 생성       증거: 프로젝트 대시보드 ____
- [ ] 5. 타 LLM 택1 (GPT/Gemini/Grok)    증거: ____
## B. 설치 5종 (+선택 1)
- [ ] 6. node -v        → 출력: ____  (v18 이상 OK)
- [ ] 7. git --version  → 출력: ____
- [ ] 8. VS Code 실행    → 증거: ____
- [ ] 9. claude --version → 출력: ____   ★ 이것만 되면 1-6 진입 가능
- [ ]10. Claude 데스크톱 로그인 → 증거: ____
- [ ] (선택) Antigravity → 증거: ____
## C. 안전 서약 (읽고 체크 — 1강 안전수칙)
- [ ] service_role 등 비밀키는 어디에도 올리지 않는다 (anon 공개키만 페이지에)
- [ ] 폼 예시에 실제 개인정보를 넣지 않는다
```

#### 단계별 지시
1. 워크시트를 열고 A→B 순서로 각 항목을 확인, 상태칸 체크.
2. 터미널 확인 3종(`node -v`, `git --version`, `claude --version`)은 출력 문자열을 그대로 붙인다.
3. ❌ 항목은 즉시 손을 들어 조교 호출(설치 순서: Node → Git → VS Code → Claude Code CLI).
4. C 안전 서약 2줄을 읽고 체크.
5. 완료 조는 옆 조 ❌ 항목을 함께 봐 준다(조 단위 완주).

#### 완료 기준 (체크리스트)
- [ ] A·B 10항목 전부 ✅ (Antigravity 선택 제외)
- [ ] `claude --version`이 버전 문자열을 출력한다
- [ ] C 안전 서약 2줄 체크
- [ ] 안전 게이트: 워크시트·화면 어디에도 키·토큰이 보이지 않는다

#### 힌트
- **힌트 1(방향)**: "계정은 GitHub부터 — Vercel·Supabase가 GitHub 로그인을 재사용해요."
- **힌트 2(접근)**: "설치가 꼬였으면 지우고 다시가 빠릅니다. 조교와 함께 재설치 5분."
- **힌트 3(골격)**: 조교가 화면을 함께 보며 설치 명령을 같이 실행(원칙⓷).

#### [조교 개입 신호]
Claude Pro 결제 실패 / `claude --version` 미출력 / Node 설치 후 터미널 재시작 안 함 → **즉시 1:1**. 블록 종료 시 미완료자 0명이 목표. 끝내 안 되면 Codespaces 우회 + 강 종료 후 보정 예약.

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: 항목 9(`claude` CLI)까지 완료 — 1-6 실습 진입 가능. 나머지는 휴식(1-4)에 조교 보정.

```text
⚠️ 확실하지 않은 통계·법조항·판례번호는 '[확인 필요]'로 표시하고 지어내지 마라.
```
```markdown
[사실검증 체크리스트 — 게시 전 필수 (2강 안전수칙)]
```

1. 완성 참조 글을 먼저 읽는다(⓶).

5. 검증 통과본을 2-A 블로그에 게시 → 게시 URL을 부품 대장에 기록.

#### 완료 기준 (체크리스트)
- [ ] 게시 URL이 열린다(2-A 본인 블로그)
- [ ] 검증 체크리스트 4항목 전부 ✅ + **실제 수정/삭제 기록 1건 이상**(무검증 통과 방지)
- [ ] 수정 루프 흔적(초안과 게시본이 다름)

- **힌트 1(방향)**: "핵심 3가지는 '독자가 이 글에서 얻어갈 것' 3개로 잡으세요."

### 실습 2-C: 유튜브 콘텐츠 세트 제작·업로드 【블록 2-8 · 30분】 ★부품: 영상 산출 포맷
**목표**: (창조) 유튜브 세트(대본·설명·썸네일 문구)를 제작해 본인 채널에 업로드한다.
**난이도**: 빈칸 채우기 → 수정 · 선행: 2-B 게시 완료(소재 재사용)

#### 시나리오
2-B 블로그 글을 소재로 **원소스 멀티유즈**를 체험한다. 촬영·편집은 이 과정의 범위가 아니다 — **대본(스크립트)·제목·설명·썸네일 문구 세트**를 만들고, 간단 영상(슬라이드 낭독·화면 녹화 등 최소형)을 **본인 채널에 실제 업로드**한다.

#### 스타터 (실제 문안)
```text
[유튜브 세트 프롬프트 — 빈칸 채워서 Claude에 붙이기]
소재: (2-B 블로그 제목) __________
아래 4가지를 만들어줘:
1) 60~90초 낭독용 대본 (인사 1줄 → 핵심 3가지 → 마무리 1줄)
2) 클릭 유도 제목 3안 (과장·허위 금지)
3) 설명문 3~4줄 + 해시태그 5개
4) 썸네일 문구 6단어 이내 2안
⚠️ 조회수 유도라도 허위 정보·과장 수치 금지. 블로그에서 검증된 내용만 사용.
```
```markdown
[업로드 절차 카드]
- [ ] 1. 대본을 소리내어 1회 읽어 어색한 문장 수정 (사람 검증)
- [ ] 2. 최소형 영상 준비: 슬라이드 1~3장 화면 녹화 + 낭독 (또는 폰 셀프 촬영 60초)
- [ ] 3. 유튜브 스튜디오 → 업로드 → 제목·설명·해시태그 붙여넣기
- [ ] 4. 공개 범위: '일부 공개(링크 공유)' 권장 — 부담 없이 시작
- [ ] 5. 영상 URL 기록: ____________
```

#### 단계별 지시
1. 세트 프롬프트로 4종(대본·제목·설명·썸네일 문구) 생성.
2. 대본을 **소리내어 읽고 수정**(어색한 AI 문장 → 내 말투).
3. 최소형 영상 1개 준비(품질보다 완주 — 60초면 충분).
4. 본인 채널 업로드('일부 공개' 권장) → URL 기록.
5. 블로그 URL + 유튜브 세트를 `02_content_format.md`로 저장(→4강 산출 포맷 부품).

#### 완료 기준 (체크리스트)
- [ ] 세트 4종이 `02_content_format.md`에 저장됨
- [ ] 본인 채널에 영상 1개 업로드됨(URL 기록) — 인증 지연 시 절차 견학으로 대체, 3강 전까지 제출
- [ ] 대본 사람 수정 흔적 1곳 이상
- [ ] 안전 게이트: 허위·과장 수치 0 · 고객정보 0

#### 힌트
- **힌트 1(방향)**: "제목은 '무엇을 얻는가'를 6~12자로. 썸네일 문구는 제목과 다른 각도로."
- **힌트 2(접근)**: "영상이 부담이면 슬라이드 1장 + 낭독 60초로 충분해요. 오늘의 목표는 '업로드 경험'입니다."

#### [조교 개입 신호]
녹화 도구를 못 찾음(OS 기본 녹화 안내) / 업로드 처리 지연 → 업로드 진행 중 상태로 다음 블록 진행 허용, 종료 전 확인.

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: 세트 4종을 `02_content_format.md`에 저장 + **업로드 절차 견학으로 대체 가능**(구글 본인인증·채널 활성화 지연 시). 이 경우 실제 업로드는 **3강 전까지** 완료해 URL을 조교 채널에 제출한다.
- **확장 과제(빠른 조)**: 썸네일 시안 2종 비교 / 챕터 타임코드 삽입 / 블로그 글에 영상 임베드.

### 실습 3-A: 회의록 생성·문서화 스킬 제작 【블록 3-4 · 45분】 ★부품: 스킬 파일 2~3개
**목표**: (창조) 단일 책임 스킬 2~3개를 스켈레톤에서 제작하고 샘플 회의 녹취록으로 테스트한다.
**난이도**: 수정(스켈레톤 빈칸+규칙 다듬기) · 선행: 블록 3-3 전 과정 시연

#### 시나리오
자동화의 레고 블록인 **스킬(만드는 것)**을 직접 만든다. 회의록 에이전트의 두뇌가 될 스킬 2개(생성·문서화)를 제작하고 합성 회의 메모로 테스트한다. 여기서 익힌 "스킬 만들기"는 다음 강(4강)의 분석·검증·요약 스킬 제작으로 그대로 확장된다.

#### 스타터 (실제 문안 — SKILL.md 스켈레톤 2종 + 합성 회의 메모)
```markdown
---
name: make-minutes            # 스킬 A: 회의록 생성 (필드 구조 수정 금지)
description: "____ 할 때 사용. '회의록 만들어'·'회의 정리해' 트리거."  # ← 빈칸: 트리거 문구
---
# 회의록 생성 스킬
## 언제 쓰나
- ____ (빈칸: 발동 상황 — 예: 회의 메모/녹취 텍스트를 붙여넣었을 때)
## 처리 규칙
1. 입력에서 '안건 → 논의 → 결정사항 → 액션아이템'을 분리   # ← 규칙 채우고 다듬기
2. 액션아이템은 '담당자·기한'을 반드시 표기 (없으면 [미정])
3. 원문에 없는 결정·수치는 추가 금지 (환각 차단)
## 출력 형식
- ____ (빈칸: 예) ## 안건 / ## 결정사항 / ## 액션아이템(담당·기한) 표
## 안전 규칙
- 참석자 실명·연락처는 이니셜/직책으로 마스킹
```
```markdown
---
name: format-doc              # 스킬 B: 문서화
description: "____ 트리거."    # ← 빈칸: 예) '문서로 정리해'·'메일 본문 만들어'
---
# 문서화 스킬
## 처리 규칙
1. 회의록 구조를 배포용 md + 메일 본문 2형식으로 변환
2. 제목/일시/참석(직책)/요약 3줄을 상단에 배치
## 출력 형식
- ____ (빈칸: 메일 제목 1줄 + 본문 + 하단 액션아이템 표)
```
```text
[합성 회의 메모 스니펫 — 테스트 입력용 (가상 안건·가명 참석자)]
7/28 월마감 점검 회의. 참석 K팀장, L대리, P사원.
미결 전표 12건 중 8건은 L대리가 수요일까지 처리하기로 함.
나머지 4건은 거래처 회신 대기. 다음 회의는 8/4 오전 10시.
법인카드 증빙 누락 3건 — P사원이 금요일까지 수집.
```

#### 단계별 지시
1. 시연 스킬(참조본)의 트리거·구조를 관찰(⓶).
2. 스킬 A 스켈레톤의 빈칸(트리거·발동 상황·출력 형식)을 채운다.
3. **실제 호출 테스트**: 합성 회의 메모를 붙이고 트리거 문구 입력 → 안건·결정·액션아이템(담당·기한) 구조가 나오는지 확인.
4. 출력이 마음에 안 들면 **처리 규칙을 수정**하고 재테스트(수정 루프 — 이것이 스킬 디버깅).
5. 스킬 B(문서화)를 같은 방식으로 완성 → A 출력을 B에 넣어 md+메일 본문 2형식 확인.
6. (확장) 스킬 C: 액션아이템 추출·검증 스킬(담당자·기한 누락 점검).
7. 산출물: `~/.claude/skills/` 아래 동작하는 스킬 2~3개.

#### 완료 기준 (체크리스트)
- [ ] 트리거 문구 입력 → 스킬 A가 발동하고 정의한 출력 형식대로 생성
- [ ] 합성 메모 입력 → 안건·결정·액션아이템(담당·기한 표기) 구조 확인
- [ ] 스킬 B: 구조화 회의록 → 배포용 md + 메일 본문 2형식 생성
- [ ] 같은 메모 2회 실행 시 동일 구조 출력(재현성 맛보기)
- [ ] 안전 게이트: 원문에 없는 결정·수치 삽입 0 · 참석자 실명 마스킹

#### 힌트
- **힌트 1(방향)**: "`description`이 곧 트리거예요. '언제 이 스킬이 켜지길 원하나'를 문장으로 쓰세요."
- **힌트 2(접근)**: "처리 규칙은 '입력 → 무엇을 → 어떻게 → 출력' 순서로 번호 매기기."
- **힌트 3(골격)**: 스킬 A 완성본 절반 공개 → 스킬 B는 구조를 복제해 학습자가 완성.

#### [조교 개입 신호]
스킬이 트리거되지 않음(→ description 문구 조정) / 스킬이 원문에 없는 결정·수치를 지어냄(→ 환각 차단 규칙 보강) / 회의 메모에 실명·연락처 방치(→ 즉시 마스킹).

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: **생성 스킬 1개**가 트리거·동작(문서화는 조교 도움 허용).
- **확장 과제(빠른 조)**: 스킬 C(액션아이템 검증) 추가 / A→B 연계 파이프를 한 문장 지시로 실행.

### 실습 3-B: Gmail 연동 발송 + 프로젝트 폴더 정리 — 회의록 에이전트 완성 【블록 3-7 · 35분】 ★부품: 동작하는 회의록 에이전트 1개
**목표**: (종합) 스킬 + Gmail MCP/커넥터 연동을 프로젝트에 담아 동작하는 회의록 에이전트로 결선한다. (평가) Gmail 연동의 데이터 행선지를 확인한다.
**난이도**: 수정 → 소규모 확장(조립) · 선행: 3-A 완성 + 블록 3-6 Gmail 연동 시연

#### 시나리오
스킬이 "내가 만든 도구"라면 **Gmail MCP/커넥터는 "외부 세계로 난 창"(연결하는 것)**이다. 3-A의 스킬들이 만든 회의록을 **Gmail로 발송**해 부품들이 처음으로 **하나의 에이전트(부리는 것)**가 되고, 이를 **프로젝트 폴더(담는 것)**에 담는다 — 개념 5종 중 4종이 여기서 실물로 조립된다. 동시에 **"이 데이터가 어디로 가는지"** 확인하는 안전 습관을 익힌다.

#### 완료 기준 (체크리스트)

# Ⅱ. 주간 과제 5건 (강 간 연결 — 매 강 종료 시 부여, 다음 강 도입 회고에서 확인)

> 주 1회 간격의 망각 곡선을 상쇄하는 v3의 핵심 장치. 각 과제는 **강 내 실습 산출물의 소폭 변형·실전 적용**이며(백지 과제 없음), 다음 강 도입 블록에서 반드시 확인한다.

## 주간 과제 ① 【1강 전 · 사전 배포】 두 안내서 숙지 + 설치·계정 사전 시도
- **내용**: ① 프로그램 설치 안내서 ② 사전과제 작성 안내서(1강 2~3일 전 배포)를 읽고, 계정 5종·설치 도구를 **미리 시도**해 온다(완료가 아니라 시도 — 완료 확인·보정은 1강 1-2에서 대면 수행).
- **제출물**: 없음(시도 상태 그대로 1강 지참). 막힌 항목은 안내서 여백에 "어디서 막혔는지" 1줄 메모.
- **확인 방법**: 1강 블록 1-2에서 10종 체크리스트로 대면 확인 — 사전 시도자가 많을수록 확인 시간이 단축된다.
- **막힘 대비**: 설치가 무서우면 계정 5종만이라도 가입해 오기. 결제(Claude Pro)가 안 되면 1강에서 조교와 함께.

## 주간 과제 ② 【1강 후 → 2강 2-1 확인】 랜딩페이지 1섹션 추가·수정해 재배포
- **내용**: 1강에서 배포한 본인 랜딩페이지에 **섹션 1개를 추가 또는 수정**하고(예: 자격증·FAQ·인사말 업데이트) 재배포한다. 1강 실습(1-B·1-C)의 소폭 변형 — 같은 배관을 혼자 한 번 더 돌려 **재현성을 체감**하는 것이 목적.
- **제출물**: 재배포된 URL(주소는 동일) + 무엇을 바꿨는지 1줄.
- **확인 방법**: 2강 블록 2-1 회고에서 조별로 URL을 다시 열어 변경 섹션을 상호 확인. 강사는 2~3명 화면 공유로 "혼자서도 배포가 됐다"를 전체 확인.
- **막힘 대비**: 힌트 ① 1-B 프롬프트 카드를 재사용해 "○○ 섹션을 추가해줘" ② push하면 Vercel이 자동 재배포 — 새로 배포 설정할 필요 없음. 그래도 막히면 주중 조교 채널에 캡처 질문.

## 주간 과제 ③ 【2강 후 → 3강 3-1 확인】 본인 직군 소재 블로그 글 1편 추가 게시
- **내용**: 2강 실습(2-B)과 같은 루프(생성→수정→**검증**→게시)로 본인 직군 소재 글 1편을 **혼자** 추가 게시한다. 검증 체크리스트 수행 필수(수정·삭제 기록 1건 이상).
- **제출물**: 게시 URL + 검증 체크리스트(수정/삭제한 내용 1건 기록 포함).
- **확인 방법**: 3강 블록 3-1 회고에서 URL 확인 + "검증에서 무엇을 걸러냈는지" 1인 1문장 공유(검증 루프 정착 확인).
- **막힘 대비**: 힌트 ① 2-B 프롬프트 템플릿 재사용, 주제만 교체 ② 소재가 없으면 직군별 소재표(2강 변형표)에서 선택. **안전**: 허위 숫자·법조항 금지 · 고객정보 프롬프트 금지.

## 주간 과제 ④ 【3강 후 → 4강 4-1 확인】 회의록 에이전트를 실제 회의 1건에 사용
- **내용**: 3강에서 만든 회의록 에이전트를 **실제 업무 회의 1건**(팀 회의·미팅 메모)에 사용한다. 실데이터 동작을 처음 체감하는 과제. 참석자 실명은 이니셜/직책으로 마스킹, 발송은 **본인 메일로만**(실제 참석자 발송은 사내 합의 전 금지).
- **제출물**: 생성된 회의록(마스킹본) + 본인 메일 수신 캡처 + "실데이터에서 무엇이 달랐는지" 1줄.
- **확인 방법**: 4강 블록 4-1 회고에서 후기 공유 — "합성 데이터와 실데이터의 차이"를 조별 1건씩 발표(5강 수료 기준 ⓵ 실데이터 동작의 예열).
- **막힘 대비**: 힌트 ① 회의가 없던 주면 과거 회의 메모 재사용 가능 ② 스킬이 실데이터에서 이상하게 동작하면 그 사례 자체가 훌륭한 공유거리 — 고치지 못해도 기록해 오기.

## 주간 과제 ⑤ 【4강 후 → 5강 5-1 점검 · ★캡스톤 핵심 입력물】 본인 업무 2~3개 I/P/O 시트 작성
- **내용**: 본인 업무 2~3개를 **입력(I)→처리(P)→출력(O)** 시트로 분해한다. **이것은 과제가 아니라 5강 실습의 입력물** — 미제출 시 5강 하네스 실습 진행 불가(커리큘럼 명시). 자동화 1순위 업무에 ★ 표시.
- **제출물**: `내문서/vibecoding/05_ipo_sheet.md` (아래 캡스톤 워크시트 W1 서식) — **5강 2일 전까지** 조교 채널 제출.
- **확인 방법**: 제출 즉시 조교가 주중 1회 서면 피드백(운영 권장 — I/P/O가 모호한 행 지적). 5강 블록 5-1에서 조별 점검 후 5-3 미러링 설계의 소재로 즉시 사용.
- **막힘 대비**: 힌트 ① 시트 템플릿에 직군 예시행 2종이 채워져 있음(아래 W1) ② "반복되고·규칙 있고·결과물이 명확한" 업무를 고르면 실패 없음 ③ 정 없으면 5-1에서 공통 프로젝트 변형 소재로 대체 제공(최소 통과선). **안전**: 시트에 고객 실명·계좌 등 기재 금지(가명·범주명만).

## 실습 5-A (워크시트 W2): 미러링 설계 — I/P/O를 하네스 설계도로 변환 【블록 5-3 · 30분】
**목표**: (분석·전이) 본인 I/P/O를 공통 하네스 구조에 대응(미러링)시켜 설계도를 완성한다.
**난이도**: 확장(전이 — 구조는 유지, 내용만 치환) · 선행: 블록 5-2 하네스화 시연 + W1

#### 시나리오
5-2 시연에서 4강 에이전트팀이 하네스(입력 고정·실행 절차·산출 규격)로 포장되는 것을 봤다. 이제 같은 구조에 **당신의 업무**를 얹는다. "수집→분석→검증→요약" 4역할 골격은 그대로 두고, **소재·스킬·연결·출력만** 바꾼다 — 이것이 미러링이다.

#### 스타터 (실제 문안 — W2 미러링 치환 워크시트)
```markdown
# W2. 4역할 매핑(미러링 치환표)  — W1의 ★ 업무 1개를 여기에 옮겨 적고 시작
★ 업무명: ____________  (W1에서 복사)

## ① I/P/O → 4역할 대응 (규칙: I=수집, P의 앞부분=분석, P의 확인부분=검증, O=요약)
| 역할 | 공통 프로젝트(원본) | → 내 업무로 치환 (빈칸) | 쓸 부품 (스킬/연결) |
|------|--------------------|------------------------|--------------------|
| 수집 | 증시·뉴스 (웹검색 MCP) | 내 입력원: ________ | ________ (예: 웹검색 MCP / 파일 읽기) |
| 분석 | 전조·패턴 3스킬 | 내 처리 규칙: ________ | ________ (예: 3강 생성 스킬 개조) |
| 검증 | 숫자·출처 교차검증 | 내 확인 항목: ________ | ________ (예: verify-cross 재사용) |
| 요약 | 브리핑 카드 | 내 출력물: ________ | ________ (예: format-doc 재사용) |

## ② 하네스 3요소 (5-2 시연에서 관찰한 것)
- 고정 입력: ________ (매번 같은 형식으로 들어올 것 — 예: 키워드 목록 / CSV 1개)
- 실행 방법: "한 문장 지시" 문안: "________________ 실행해줘"
- 산출 규격: ________ (파일명 규칙 포함 — 예: 결과_{날짜}.md, 표 3열 고정)

## ③ 출력 행선지 (부품 이월)
- [ ] 파일 저장만  [ ] 1강 페이지/Supabase 게시  [ ] 2강 블로그 게시  [ ] Gmail 발송(본인 메일)
```

#### 단계별 지시
1. W1의 ★ 업무를 W2 상단에 옮겨 적는다.
2. ① 치환표: I=수집, P=분석·검증, O=요약 규칙으로 4행을 채운다. "쓸 부품" 열은 **기존 부품 재사용 우선**(3강 스킬·4강 검증 스킬).
3. ② 하네스 3요소(고정 입력·실행 문안·산출 규격)를 확정한다 — 5-6 재실행 검증에서 이 문안을 2회 그대로 사용한다.
4. ③ 출력 행선지 택1 이상.
5. 조 내 상호 검토 1회: "이 설계도만 보고 남이 만들 수 있나?"를 서로 묻는다.

#### 완료 기준 (체크리스트)
- [ ] 치환표 4행이 전부 구체적으로 채워짐(모호어 0)
- [ ] 하네스 3요소(고정 입력·실행 문안·산출 규격) 확정
- [ ] 재사용 부품이 1개 이상 지정됨(3·4강 이월)
- [ ] 조 내 상호 검토 1회 완료
- [ ] 안전 게이트: 설계도에 고객 실명·기밀 0(가명·범주명만)

#### 힌트
- **힌트 1(방향)**: "W1의 I/P/O가 이미 답이에요. 입력(I)=수집, 처리(P)=분석·검증, 출력(O)=요약."
- **힌트 2(접근)**: "3강에서 만든 본인 스킬을 '쓸 부품' 열에 그대로 끼우면 절반은 끝."
- **힌트 3(골격)**: 조교가 아래 직군별 미러링 예시로 1행 시범 치환.

#### [조교 개입 신호]
미러링 대상이 자동화 부적합(판단 100% 사람 몫) → 4역할 중 자동화 가능한 부분만 도려내 재설계 안내 / 검증 행이 비어 있음 → "무엇이 틀리면 사고인가"를 물어 확인 항목 도출.

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: 공통 프로젝트 변형 소재(조교 제공)로 치환표 완성.
- **확장 과제(빠른 조)**: 2번째 업무(W1의 다른 행)도 치환표 작성.

#### 직군별 미러링 예시 (5-3 배포자료 — 3개 이상 필수, 5종 제공)
| 직군 | ★업무 예 | 수집(I) | 분석(P) | 검증(P) | 요약(O) |
|------|---------|---------|---------|---------|---------|
| **회계·세무** | **월마감 자동화** | 은행 CSV·전표 목록 읽기 | 대사·차이 검출·원인 분류 | 차이 금액 재계산·원장 대조 | 대사 결과표 + 미결 목록 |
| **법무** | **판례 요약 브리핑** | 사건 키워드로 판례·입법예고 수집 | 담당 분야 쟁점 추출 | 판례번호·조문 원문 대조 | 쟁점 요약 메모 |
| **MICE** | **행사 일정 수집** | 업종·지역 키워드로 컨퍼런스/전시 검색 | 자사 타깃 행사 선별 | 일시·장소·주최 공식 페이지 확인 | 월간 행사 캘린더 |
| 미디어 | 산업 뉴스 큐레이션 | 주제 키워드 뉴스 수집 | 이번 주 핵심 흐름 분석 | 사실·수치 팩트체크 | 데스크 브리핑 카드 |
| 투자 | 종목 동향 스캔 | 관심 종목·지수 뉴스 수집 | 전조·이벤트 인사이트 | 숫자·출처 교차검증 | 의사결정 카드 |

## 실습 5-B (워크시트 W3): 하네스 개발 1부 — 공통 하네스 복제·개조 【블록 5-5 · 40분】 ★조교 밀착
**목표**: (창조) 설계도(W2)대로 하네스를 복제·개조하고 본인 업무 데이터(가명화)로 1차 실행한다.
**난이도**: 확장(캡스톤 본체) · 선행: W2 완성 · 도구: 에신Lite + Claude Code CLI

#### 스타터 (실제 문안 — W3 결선 워크시트 + 복제 절차 카드)

5. W3 기록표를 `harness_mine/README.md`로 저장 — **실행 문안은 이후 변경 금지**(5-C에서 그대로 2회 사용).

- [ ] W3 기록표(README) 저장 완료
- [ ] 안전 게이트: 투입 데이터 가명화 조교 확인 · 비밀키 하드코딩 0

#### 힌트
- **힌트 1(방향)**: "새로 만들지 마세요. 복제→개조가 미러링입니다. 골격을 건드리면 배관이 끊어져요."
- **힌트 2(접근)**: "4역할을 한 번에 고치지 말고, collector 고치고 단독 실행 → 통과하면 다음."
- **힌트 3(골격)**: 조교가 collector 개조 1건을 함께 수행(에신Lite 지시 문안 시범).

#### [조교 개입 신호]
실데이터에 고객 실명·계좌 발견(→ 즉시 가명화, 투입 중단) / 복제 대신 처음부터 새로 만들기 시작(→ 복제 절차로 회귀) / 1차 실행이 특정 역할에서 반복 실패(→ 그 역할만 공통 프로젝트 원본으로 되돌려 범위 축소).

#### [최소 통과선 / 확장 과제]

- [ ] 편차 0 또는 수정 후 재검증 통과
- [ ] 안전 게이트: 재현성 확인 전 "완성" 선언 금지 준수

#### [조교 개입 신호]

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: 5항목 중 4항목 동일 + 편차 원인·조치 기록(보완 판정으로 5-D 진행 — 사후 점검에서 마무리).
- **확장 과제(빠른 조)**: 입력을 바꾼 3회차 실행(다른 데이터에도 규격 유지되는지) / 실패 시 재시도 규칙 삽입.

```markdown
- [ ] 하네스 산출 영상/기록: ____________ (2회 실행 화면 녹화 또는 W4+산출물 2쌍)

판정 결과:  [ ] 수료 (A 3기준 전부 통과 + B 게이트 전부 ✅)
           [ ] 보완 (보완 항목: ______ → 수료 후 온라인 사후 점검 60분에서 마무리)
```

#### 단계별 지시
1. A표를 자가진단으로 채운다 — "내 증거" 칸은 파일명·기록 등 **구체물**로(빈말 금지).
2. B 게이트 5항목 자기점검 — ②는 조교의 가명화 확인 서명 필요.
3. 강사가 조별 순회하며 증거를 열어 확인 → 강사판정 기입.
4. 판정 기록을 `harness_mine/final_rubric.md`로 저장 → 5-8 발표(하네스 시연 + 확산 계획 1줄)로 이동.

#### 판정 규칙
- **수료** = A 3기준 전부 통과 **+** B 게이트 5항목 전부 ✅. B는 점수가 아니라 게이트 — 하나라도 위반 시 산출물 반려 후 재실행(3기준 통과여도 수료 불가).
- **보완** = A 중 1개 이상 보완 → 수료 후 온라인 사후 점검(운영 옵션 60분)에서 마무리 가능.
- 5-8 사내 공유 저장소 등재는 **B-⑤ 통과자만**(비밀키·내부정보 제거 확인 후).
