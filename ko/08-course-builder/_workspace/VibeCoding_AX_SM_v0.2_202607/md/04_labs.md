## 0. 설계 관통 규약 (모든 실습에 강제 적용)

### 0.1 3대 설계원칙 준수 방식
| 원칙 | 본 실습설계 반영 방식 |
|------|----------------------|
| **⓵ 백지 시작 금지** | 모든 실습에 **스타터 파일(스켈레톤/템플릿/프롬프트 카드)**를 배포한다. 학습자는 "채우기 → 고치기 → 확장하기"만 한다. 빈 화면·빈 파일에서 시작하라는 지시는 없다. |
| **⓶ 데모 먼저** | 각 실습 시작 시 **완성 산출물(참조본)**을 먼저 제시한다. 학습자는 "무엇이 나오는지" 눈으로 본 뒤 손을 움직인다. 참조본은 조교가 미리 배포/실행해 둔다. |
| **⓷ 강사+조교 배석** | 각 실습에 **[조교 개입 신호]**를 명시했다. 3인 1조 중 한 명이 막히면 조 전체가 멈추므로, 신호 발생 시 조교가 즉시 개입한다. |

### 0.2 실습 유형 5단계 피라미드 배치
lab-scaffolding 피라미드를 8시간 압축과정에 맞춰 배치했다. 초보자 대상이므로 뒤로 갈수록 자율성을 서서히 올린다.

| 강 | 실습 | 피라미드 단계 | 학습자 자율성 | 스타터 형태 |
|----|------|--------------|--------------|------------|
| 0강 | 사전과제 | 1~2 (따라하기·워크시트) | 20% | 체크리스트 + I/P/O 워크시트(예시행 채워짐) |
| 1강 | 랜딩페이지 배포 | 2 (가이드 실습) | 20% | HTML 스켈레톤 + 배포 절차 카드(빈칸) |
| 2강 | 콘텐츠 엔진 | 2→3 (가이드→챌린지) | 40% | 프롬프트 템플릿(빈칸) + 검증 체크리스트 |
| 3강 | 스킬·MCP 제작 | 3 (챌린지·힌트) | 50% | SKILL.md 스켈레톤 + MCP 설정 스니펫 |
| 4강 | 하네스 캡스톤 | 4→5 (미니→캡스톤) | 80~95% | 4역할 에이전트 스켈레톤 + 하네스 결선 골격 |

### 0.3 3단 힌트 시스템 (전 실습 공통 — 조별 진도 편차 흡수)
막히면 아래 순서로만 개입한다. **정답을 바로 주지 않는다.**

```
[스스로 시도]  ── 3분 경과 ──▶
[힌트 1·방향]  "이건 ○○ 개념이에요. 배포자료의 △△ 섹션을 보세요."  ── 3분 ──▶
[힌트 2·접근]  "이 프롬프트/설정을 여기에 붙여 보세요: (일부 공개)"      ── 3분 ──▶
[힌트 3·골격]  "구조는 이래요: (코드/설정 스켈레톤 절반 공개)"          ── 3분 ──▶
[조교 1:1]    화면 공유로 함께 완성 → 반드시 "왜 이렇게 되는지" 1줄 회고
```
- **빠른 조**: 각 실습의 `[확장 과제]`로 상향(추가 제약·기능 1개).
- **느린 조**: 각 실습의 `[최소 통과선]`만 달성하면 통과(다음 강 진입 자격 확보).

### 0.4 누적 부품 이월 대장 (Carryover Ledger)
각 실습 산출물은 **다음 강에서 재사용 가능한 형태**로 아래 고정 경로에 저장한다. 조교가 매 강 종료 시 저장 여부를 확인한다.

| 산출 강 | 부품 | 저장 형태·위치 | 소비 강 | 소비 방식 |
|---------|------|---------------|---------|----------|
| 0강 | 본인 업무 I/P/O 시트 | `내문서/vibecoding/00_ipo_sheet.md` | 4강 | 미러링 시드(4-5) |
| 0강 | 도구 10종 체크리스트 | 스크린샷 폴더 | 1~4강 | 환경 선수조건 |
| 1강 | 배포된 랜딩페이지 URL + repo | Vercel URL + GitHub repo | 4강 | 하네스 **출력/배포 채널** |
| 2강 | 콘텐츠 포맷(블로그·유튜브 세트) | `내문서/vibecoding/02_content_format.md` | 4강 | 요약 에이전트 **산출 포맷** |
| 3강 | 스킬 2~3개 + MCP 설정 | `~/.claude/skills/*` + `.mcp.json` | 4강 | 4역할 **부품 재료** |
| 4강 | 에이전트팀 하네스 | `내문서/vibecoding/harness/` 프로젝트 폴더 | 클리닉 | 정착·확산 |

### 0.5 안전 게이트 (전 실습 공통 — 위반 시 산출물 반려)
모든 실습은 제출 전 아래 4게이트를 **자기점검 체크박스**로 통과해야 한다. 하나라도 위반 시 반려 후 재실행.

- [ ] **① 비밀키 노출 0**: `service_role`·API 키·토큰이 코드·화면·스크린샷·프롬프트 어디에도 없다. (공개키 `anon`만 허용)
- [ ] **② 고객/개인정보 입력 0**: 실명·주민번호·계좌·연락처·고객 식별정보를 폼 예시·프롬프트·테스트 데이터에 넣지 않았다. (합성/가명 데이터만)
- [ ] **③ 검증 단계 수행**: AI 생성 숫자·법조항·출처를 사람이 확인했다. (2강 이후 필수)
- [ ] **④ 데이터 흐름·최종 확인**: MCP가 데이터를 어디로 보내는지 확인했고, 대외 산출 전 최종 확인을 사람이 했다. (3강·4강)

## 0강 사전과제 — "본인 업무 I/P/O 시트 + 도구 정렬"

### 실습 0-A: 도구 10종 온보딩 체크리스트
**매핑 학습목표**: (적용) 도구 10종을 설치·로그인하고 체크리스트를 완료할 수 있다. (0-2·0-3)
**예상 소요시간**: 40분 (실습 0-B와 합쳐 60~90분)
**난이도**: 초급 · **피라미드 1단계(따라하기)**

#### 시나리오
당신은 선명AG 정규직이며 코딩 경험이 전혀 없다. 본과정 첫 실습(1강 배포)에 들어가려면 그 전에 "연장"부터 손에 쥐어야 한다. 가이드 영상을 보며 계정·설치를 그대로 따라 완료한다.

#### 과제 지시
1. 배포된 **체크리스트 워크시트**(아래 스타터)를 연다.
2. 각 항목을 순서대로 완료하고, **완료 증거**(스크린샷 또는 CLI 출력)를 붙인다.
3. 마지막 CLI 항목에서 `claude` 실행이 성공하면 캡처한다.
4. 제출물: 완료된 체크리스트 + 증거 스크린샷 폴더.

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: 항목·순서·확인 명령어·안전 경고가 이미 적힌 워크시트.
> **빈칸**: `[완료✅/미완❌]` 상태칸과 증거 링크칸만 학습자가 채운다.

```markdown
# 0강 도구 온보딩 체크리스트  (상태칸만 채우세요)
## A. 계정 5종
- [ ] Claude Pro 결제 완료        증거: ____   ⚠️ 해외결제 카드 필요
- [ ] GitHub 가입·로그인          증거: ____
- [ ] Vercel 가입(GitHub 연동)    증거: ____
- [ ] Supabase 프로젝트 1개 생성   증거: ____
- [ ] 타 LLM 택1(GPT/Gemini/Grok) 증거: ____
## B. 설치 6종  (터미널 출력 붙이기)
- [ ] node -v      →  출력: ____   (v18 이상이면 OK)
- [ ] git --version →  출력: ____
- [ ] VS Code 실행  →  증거: ____
- [ ] claude --version → 출력: ____
- [ ] Claude 데스크톱 로그인 → 증거: ____
- [ ] (선택) Antigravity → 증거: ____
## C. 안전 서약 (반드시 읽고 체크)
- [ ] service_role 등 비밀키는 화면·스크린샷·업로드 어디에도 올리지 않는다.
```

- **힌트 1(방향)**: "계정은 GitHub부터. Vercel·Supabase가 GitHub 로그인을 재사용해요."
- **힌트 2(접근)**: "설치가 막히면 `claude` CLI만 되면 1강은 진입 가능. 나머지는 조교가 강 시작 전 보정."
- **힌트 3(골격)**: 조교가 원격 화면공유로 설치 명령을 함께 실행.

#### [조교 개입 신호]
- Claude Pro 결제 실패 / `claude --version`이 뜨지 않음 / Node 설치 후 `node -v` 미출력 → **즉시 1:1 원격 지원**. 강 시작 전 미완료자 0명이 목표.

#### 완료 판정 기준 (동작 확인)
- A·B 항목 전부 `✅` + 증거 첨부.
- 터미널에서 `claude --version`이 버전 문자열을 출력한다(스크린샷 확인).
- **안전 게이트**: 붙인 스크린샷 어디에도 키·토큰이 보이지 않는다.

### 실습 0-B: 본인 업무 I/P/O 시트 (★ 4강 미러링 시드)
**매핑 학습목표**: (적용) 본인 업무 2~3개를 입력→처리→출력 형식으로 기술할 수 있다. (0-4)
**예상 소요시간**: 20분
**난이도**: 초급 · **피라미드 2단계(워크시트 빈칸 채우기)**

#### 시나리오
4강에서 당신은 공통 프로젝트(뉴스 인사이트 에이전트팀)를 **본인 업무로 복제**한다. 그 복제의 원본 설계도를 지금 그린다. 반복적이고·규칙이 있고·결과물이 명확한 업무일수록 자동화가 잘 된다.

#### 과제 지시
1. 예시행이 채워진 **I/P/O 워크시트**(스타터)를 연다.
2. 본인 업무 **2~3개**를 골라 각 행의 **입력(I)·처리(P)·출력(O)·현재 소요시간·반복주기**를 채운다.
3. 자동화 우선순위 1순위 업무에 `★` 표시.
4. 제출물: `내문서/vibecoding/00_ipo_sheet.md`로 저장(4강까지 보관).

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: 표 구조 + **직군 예시행 1개**(본인 직군에 맞는 것 참고).
> **빈칸**: 본인 업무 행 2~3개.

```markdown
# 내 업무 I/P/O 시트   (예시행 참고해 본인 업무 2~3개 채우기)
| ★ | 업무명 | 입력(I) | 처리(P) | 출력(O) | 현재 소요 | 반복주기 |
|---|--------|---------|---------|---------|----------|----------|
|   | (예·회계) 월마감 대사 | 은행거래내역 CSV | 전표와 대사·차이 표시 | 대사 결과표 | 3시간 | 매월 |
| ★ | (내 업무1) ____ | ____ | ____ | ____ | ____ | ____ |
|   | (내 업무2) ____ | ____ | ____ | ____ | ____ | ____ |
```

- **힌트 1**: "'입력이 뭐고 결과가 뭔지'가 명확한 업무를 고르세요. 판단이 100% 사람 몫인 업무는 부적합."
- **힌트 2**: "처리(P)를 '수집→분석→검증→요약' 4동사로 쪼갤 수 있으면 4강 4역할에 딱 맞아요."
- **힌트 3**: 직군별 예시행(아래 미러링표) 제시.

#### [조교 개입 신호]
- "자동화할 업무가 없다"고 막힘 → 반복·규칙 업무 찾기 질문("매주 같은 자료 만드나요? 어디서 자료를 모으나요?").

#### 완료 판정 기준
- 업무 2개 이상이 I·P·O 3열 모두 구체적 명사로 채워짐("잘 정리한다" 같은 모호어 금지).
- 1순위 업무 `★` 1개 지정.
- **안전 게이트**: 시트에 실제 고객명·계좌 등 개인정보 없음(가명·범주명만).

#### 직군별 미러링 예시 (I/P/O 시드)
| 직군 | 예시 업무 | 입력(I) | 처리(P) | 출력(O) |
|------|----------|---------|---------|---------|
| 회계·세무 | 월마감 대사 | 은행 CSV·전표 | 대사·차이 검출 | 대사 결과표 |
| 법무 | 판례 요약 | 사건 키워드 | 판례 수집·쟁점 추출·검증 | 쟁점 요약 메모 |
| 미디어 | 산업 뉴스 큐레이션 | 주제 키워드 | 뉴스 수집·선별·팩트체크 | 데스크 브리핑 |
| MICE | 행사 일정 수집 | 업종·지역 | 컨퍼런스/전시 검색·정리 | 월간 행사 캘린더 |
| 투자 | 종목 동향 스캔 | 관심 종목·지수 | 뉴스·지표 수집·교차검증 | 의사결정 카드 |

## 1강 실습 — "스켈레톤에서 실배포 랜딩페이지까지"

### 실습 1-1: 랜딩페이지 프론트 채우기 (조별 따라하기)
**매핑 학습목표**: (적용) 강사 스켈레톤에서 출발해 자연어 지시로 랜딩페이지 프론트를 완성한다. (1-4)
**예상 소요시간**: 35분
**난이도**: 초급 · **피라미드 2단계(가이드 실습·빈칸 채우기)**

#### 시나리오
당신은 본인 직무의 **상담 접수 랜딩페이지**를 만든다(회계=세무상담 접수, 법무=법률상담 접수 등). 강사가 방금 시연한 완성본이 참조본이다. 백지에서 만들지 않는다 — 제공된 스켈레톤의 **TODO 자리**를 자연어 지시로 채운다.

#### 과제 지시
1. 조교가 배포해 둔 **완성 참조 페이지**를 먼저 연다(⓶ 데모 먼저).
2. 스타터 repo를 열고 Claude Code에 자연어로 지시해 TODO 3곳을 채운다:
   - TODO 1: 히어로 문구(본인 직무 소개)
   - TODO 2: 상담 접수 폼 필드(이름·연락·상담유형·내용)
   - TODO 3: 색·로고 등 브랜딩
3. 로컬 미리보기로 화면 확인.
4. 제출물: 완성된 프론트(다음 실습 1-2에서 배포).

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: 실행되는 HTML/CSS 골격 + 헤더·푸터·레이아웃(학습 목표와 무관한 보일러플레이트 완비).
> **빈칸(TODO)**: 히어로 카피·폼 필드·브랜딩 3곳. 각 TODO에 **채우기용 프롬프트 카드** 동봉.

```html
<!-- index.html  (스타터: 그대로 실행됨. TODO 3곳만 자연어로 채우기) -->
<!DOCTYPE html><html lang="ko"><head><meta charset="utf-8">
  <title>상담 접수</title><link rel="stylesheet" href="style.css"></head>
<body>
  <header>__(수정 금지: 로고 슬롯)__</header>

  <!-- TODO 1: 히어로 문구 -->
  <!-- 프롬프트 카드 → "이 히어로 섹션에 '○○ 직무 상담 접수' 헤드라인과
       한 줄 부제를 넣어줘. 버튼 문구는 '상담 신청'." -->
  <section class="hero"></section>

  <!-- TODO 2: 상담 접수 폼 (name/phone/type/message) -->
  <!-- 프롬프트 카드 → "이름·연락처·상담유형(select)·상담내용(textarea)
       입력 폼을 만들어줘. 전송 버튼 포함." -->
  <form id="lead-form"></form>

  <footer>__(수정 금지)__</footer>
  <script src="app.js"></script>  <!-- 1-2에서 Supabase 연결 -->
</body></html>
```

- **힌트 1(방향)**: "히어로부터. 프롬프트 카드 문구를 Claude Code에 그대로 붙이고 직무만 바꾸세요."
- **힌트 2(접근)**: "폼이 안 뜨면 '폼 필드 4개를 하나씩 만들어줘'로 쪼개서 지시."
- **힌트 3(골격)**: 폼 HTML 절반 공개(input 2개까지) → 나머지 학습자 완성.

#### [조교 개입 신호]
- 미리보기가 흰 화면 / Claude가 파일 전체를 갈아엎음 / TODO 밖을 건드림 → 즉시 개입, "TODO 주석 사이만 바꿔달라고 지시"로 교정.

#### 완료 판정 기준
- 로컬 미리보기에서 히어로 문구·상담 폼·브랜딩이 보인다.
- 폼에 텍스트 입력이 가능하다(전송은 1-2에서 연결).

### 실습 1-2: 배포 3종 세트 — GitHub → Vercel + Supabase (★ 부품: 배포 URL)
**매핑 학습목표**: (창조) 실제 URL로 배포하고 폼 데이터를 Supabase에 저장한다. (1-5)
**예상 소요시간**: 30분
**난이도**: 중급 · **피라미드 2단계(절차 카드 빈칸)**

#### 시나리오
1-1에서 만든 페이지를 **인터넷에 실배포**하고, 폼 제출이 **Supabase DB에 실제로 쌓이는지** 확인한다. 이 URL은 4강 하네스의 출력/배포 채널로 재사용된다.

#### 과제 지시
1. 참조본이 이미 인터넷에 떠 있음을 확인(⓶).
2. **배포 절차 카드**의 빈칸 명령을 실행: GitHub push → Vercel import → 배포.
3. Supabase에 `leads` 테이블을 만들고, 프론트에 **anon 공개키만** 연결.
4. 배포 URL에서 폼을 실제 제출 → Supabase 테이블에 행이 생기는지 확인.
5. 제출물: **배포 URL** + Supabase에 저장된 테스트 행 1개(가명 데이터).

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: 단계별 명령·SQL·환경변수 자리 표시가 적힌 절차 카드 + `app.js`의 Supabase 클라이언트 골격.
> **빈칸**: 본인 Supabase **프로젝트 URL**과 **anon 키**(공개키), 배포 시 repo 이름.

```javascript
// app.js  (스타터: __빈칸__ 2곳만 본인 값으로. service_role 절대 금지)
const SUPABASE_URL = "__여기에_프로젝트_URL__";
const SUPABASE_ANON_KEY = "__여기에_anon_공개키__";   // ⚠️ anon만! service_role 넣으면 반려
const sb = supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY);

document.getElementById("lead-form").addEventListener("submit", async (e) => {
  e.preventDefault();
  const f = e.target;
  // TODO: insert 한 줄 — 힌트: sb.from("leads").insert({...})
  //  name/phone/type/message 를 폼에서 읽어 넣기
});
```
```sql
-- Supabase SQL 에디터에 붙여 실행 (테이블 스타터)
create table leads (
  id bigint generated always as identity primary key,
  name text, phone text, type text, message text,
  created_at timestamptz default now()
);
alter table leads enable row level security;
create policy "anon insert" on leads for insert to anon with check (true);
```

- **힌트 1**: "URL/키는 Supabase → Project Settings → API. `anon public`이라 적힌 것만."
- **힌트 2**: "insert가 안 되면 브라우저 콘솔 에러를 Claude에 붙여넣고 '고쳐줘'."
- **힌트 3**: `sb.from("leads").insert({ name: f.name.value, ... })` 절반 공개.

#### [조교 개입 신호]
- Vercel 빌드 실패 / 폼 제출 시 콘솔 401·RLS 에러 / **service_role 키를 붙이려 함** → 즉시 개입. 키 사고는 최우선 차단.

#### 완료 판정 기준 (동작 확인)
- 배포 URL이 인터넷에서 열린다(조원 다른 PC/폰에서도 접속).
- 폼에 가명 데이터 제출 → Supabase `leads` 테이블에 행 1개 생성 확인.
- **안전 게이트**: 페이지 소스·repo에 `anon` 키만 있고 `service_role` 없음. 폼 예시에 실제 개인정보 없음.

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: URL이 열리고 폼이 보인다(DB 저장은 조교 도움 허용).
- **확장 과제(빠른 조)**: 제출 성공 시 "감사합니다" 토스트 추가 / 상담유형별 색상 배지 / 간단 관리자 목록 페이지(anon read 정책).

#### 직군별 미러링 변형
| 직군 | 페이지 주제 | 폼 필드 변형 |
|------|------------|-------------|
| 회계·세무 | 세무상담 접수 | 상담유형(종소세·법인·부가세)·희망일 |
| 법무 | 법률상담 접수 | 사건분야(민사·형사·가사)·긴급도 |
| 미디어 | 취재·제보 접수 | 제보유형·매체 |
| MICE | 행사 문의 접수 | 행사규모·희망시기·유형(전시·컨퍼런스) |
| 투자 | IR·투자문의 접수 | 관심분야·투자규모대(범주) |

## 2강 실습 — "콘텐츠 엔진: 생성-검증 루프"

### 실습 2-1: 블로그 글 1편 작성·게시 + 사람 검증 (★ 부품: 콘텐츠 포맷)
**매핑 학습목표**: (창조) 자기 직군 소재로 블로그 1편을 완성·게시하고 사실 근거를 사람이 검증한다. (2-5·2-7)
**예상 소요시간**: 30분
**난이도**: 중급 · **피라미드 2→3단계(템플릿 채우기 → 검증 챌린지)**

#### 시나리오
당신은 본인 직군 소재로 블로그 글 1편을 만든다. 핵심 훈련은 **"AI는 문장, 사실 근거는 사람이 준다"** — AI가 쓴 숫자·법조항·통계를 **사람이 검증**하는 루프를 몸에 익힌다. 이 콘텐츠 포맷은 4강 요약 에이전트의 산출 포맷이 된다.

#### 과제 지시
1. 완성 참조 블로그 글을 먼저 읽는다(⓶).
2. **프롬프트 템플릿**(스타터)의 빈칸(주제·독자·톤·핵심3)을 본인 직군으로 채워 초안 생성.
3. **검증 체크리스트**로 초안의 모든 숫자·법조항·인용을 **사람이 확인**(근거 없으면 삭제/수정).
4. 검증 통과본을 게시(사내 블로그/노션/GitHub Pages 중 택1).
5. 제출물: **게시 URL** + 검증 체크리스트(무엇을 확인/수정했는지).

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: 역할·구조·톤 지시가 완비된 프롬프트 뼈대 + 검증 체크리스트.
> **빈칸**: 주제·타깃 독자·핵심 메시지 3개·금지어.

```text
[블로그 생성 프롬프트 템플릿 — 빈칸만 채우기]
너는 __(직군)__ 실무자를 위한 블로그 작성자다.
주제: __________
독자: __________ (예: 중소기업 재무담당자)
톤: 신뢰감 있고 쉬움. 전문용어는 1줄 정의.
반드시 포함할 핵심 3가지: 1)___ 2)___ 3)___
분량: 1,000~1,500자, 소제목 3개.
⚠️ 확실하지 않은 통계·법조항·판례번호는 '[확인 필요]'로 표시하고 지어내지 마라.
```
```markdown
[사실검증 체크리스트 — 게시 전 필수]
- [ ] 본문의 모든 숫자/통계에 출처를 확인했다 (없으면 삭제)
- [ ] 법조항·판례번호·규정을 원문과 대조했다
- [ ] '[확인 필요]' 표시가 남아있지 않다 (전부 검증 또는 삭제)
- [ ] 고객·개인정보가 예시에 없다
```

- **힌트 1**: "핵심 3가지는 '독자가 이 글을 읽고 얻을 것' 3개로 잡으세요."
- **힌트 2**: "AI가 '2023년 통계에 따르면…'이라 쓰면 그게 바로 검증 대상. 출처를 못 대면 지웁니다."
- **힌트 3**: 검증된 문단 예시 1개 제시(전/후 비교).

#### [조교 개입 신호]
- 검증 없이 바로 게시하려 함 / '[확인 필요]'를 그대로 게시 → **즉시 개입**. 이 강의 핵심 원칙 위반이므로 반드시 잡는다.

#### 완료 판정 기준 (동작 확인)
- 게시 URL이 열린다.
- 검증 체크리스트 4항목 전부 `✅`이며, **최소 1건 이상 실제 수정/삭제 흔적**이 있다(무검증 통과 방지).
- **안전 게이트**: 허위 숫자·법조항 0, 개인정보 0.

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: 검증된 800자 글 게시.
- **확장 과제**: 같은 소재로 2개 톤(격식/캐주얼) A/B 생성 후 비교 회고.

## 3강 실습 — "부품 제작: 스킬 2~3개 + MCP 연결"

**매핑 학습목표**: (창조) 본인/공통 업무용 동작 스킬을 제작·테스트한다. (3-4)
**예상 소요시간**: 30분
**난이도**: 중급 · **피라미드 3단계(챌린지·힌트)**

#### 시나리오
자동화의 "레고 블록"인 **스킬**을 직접 만든다. 4강 4역할 에이전트가 이 스킬들을 부품으로 쓴다. 최소 2개(요약 스킬 + 정리 스킬), 여유되면 3개(검증 스킬).

   - 스킬 A: **요약 스킬**(긴 텍스트 → 핵심 5줄) — 4강 요약 에이전트 부품
   - 스킬 B: **정리/추출 스킬**(뉴스/문서 → 표 형태 데이터) — 4강 분석 에이전트 부품
3. 각 스킬을 **실제 호출해 테스트**(트리거 문구 → 원하는 출력 확인).
4. (확장) 스킬 C: **검증 스킬**(숫자·출처 교차확인 체크리스트) — 4강 검증 에이전트 부품.
5. 제출물: `~/.claude/skills/` 아래 동작하는 스킬 2~3개.

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: frontmatter 구조·섹션 헤더·트리거 슬롯이 있는 SKILL.md 뼈대.
> **빈칸**: `description`(트리거 문구), 처리 규칙 본문, 출력 형식.

```markdown
---
name: summarize-5lines            # 스킬 A 예 (수정 금지 필드 구조)
description: "____ 할 때 사용. '요약해줘'·'핵심만' 트리거."   # ← 빈칸: 트리거
---
# 5줄 요약 스킬
## 언제 쓰나
- ____ (빈칸: 발동 상황)
## 처리 규칙
1. 입력 텍스트에서 핵심 주장 5개 추출          # ← 규칙 채우기
2. 각 1줄, 숫자·고유명사 보존
3. 출처가 있으면 끝에 (출처) 표기
## 출력 형식
- ____ (빈칸: 예) 불릿 5개 + 한줄 총평
## 안전 규칙
- 원문에 없는 숫자·사실 추가 금지 (환각 차단)
```

- **힌트 1(방향)**: "`description`이 곧 트리거예요. '언제 이 스킬이 켜지길 원하나'를 문장으로."
- **힌트 2(접근)**: "처리 규칙은 '입력 → 무엇을 → 어떻게 → 출력' 순서로 번호 매기기."
- **힌트 3(골격)**: 요약 스킬 완성본 절반 공개 → 정리 스킬은 구조 복제해 학습자 완성.

#### [조교 개입 신호]
- 스킬이 트리거되지 않음 / 스킬이 원문에 없는 내용을 지어냄(환각) → 개입. `description` 트리거 문구 조정 + 안전 규칙 추가로 교정.

#### 완료 판정 기준 (동작 확인)
- 트리거 문구 입력 → 스킬이 발동하고 **정의한 출력 형식대로** 결과 생성.
- 요약 스킬: 임의의 뉴스 문단 입력 → 핵심 5줄 + 숫자 보존 확인.
- 정리 스킬: 뉴스 3건 입력 → 표(제목·요지·출처) 생성 확인.
- **안전 게이트**: 스킬 출력에 원문에 없는 수치가 삽입되지 않음(2건 테스트로 재현성 확인).

#### [최소 통과선 / 확장 과제]
- **최소 통과선**: 스킬 **1개**가 트리거·동작.
- **확장 과제**: 검증 스킬 C 추가 / 스킬 간 연계(요약→정리 파이프).

### 실습 3-2: MCP 연결 — 외부 데이터 가져오기 (★ 부품: MCP 설정)
**매핑 학습목표**: (적용) MCP를 연결해 외부 데이터를 가져온다. (3-5)
**예상 소요시간**: 25분
**난이도**: 중급 · **피라미드 3단계**

#### 시나리오
스킬이 "내가 만든 도구"라면 MCP는 "외부 세계로 난 창"이다. **웹검색 MCP**를 연결해 실시간 뉴스·지수를 가져온다. 이 연결은 4강 수집 에이전트의 손발이 된다. 동시에 **"이 데이터가 어디로 가는지"** 확인하는 안전 습관을 익힌다.

#### 과제 지시
1. 시연에서 MCP가 실시간 데이터를 물어오는 장면 관찰(⓶).
2. **MCP 설정 스니펫**(스타터)의 빈칸을 채워 웹검색 MCP를 연결.
3. 연결 후 "오늘 나스닥/코스피 주요 뉴스 3건 가져와" 등으로 **실데이터 수집 테스트**.
4. **데이터 흐름 점검**: 이 MCP가 무엇을 어디로 보내는지 1줄로 기록.
5. 제출물: 동작하는 `.mcp.json` + 수집 테스트 결과 캡처.

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: MCP 설정 JSON 구조 + 서버 이름 슬롯.
> **빈칸**: 사용할 MCP 서버 지정, (필요 시) 키는 **환경변수 참조**로만.

```jsonc
// .mcp.json  (스타터: 서버명·env 참조만 채우기. 키를 직접 붙여넣지 말 것)
{
  "mcpServers": {
    "web-search": {
      "command": "____",           // 빈칸: 웹검색 MCP 실행 명령
      "args": [],
      "env": { "SEARCH_API_KEY": "${SEARCH_API_KEY}" }  // ⚠️ 값이 아니라 참조!
    }
  }
}
```
```markdown
[데이터 흐름 점검표 — 필수 기록]
- 이 MCP가 보내는 것: (예) 검색 쿼리 문자열
- 보내는 곳: (예) 검색 제공자 서버
- 받아오는 것: (예) 뉴스 제목·URL·요약
- 고객/기밀 정보를 쿼리에 넣지 않는다: [ ] 확인
```

- **힌트 1**: "MCP는 설정 후 Claude Code 재시작해야 잡혀요." · **힌트 2**: "키는 절대 JSON에 직접 X → `${환경변수}` 참조."
- **힌트 3**: 동작하는 최소 설정 1개 공개.

#### [조교 개입 신호]
- MCP 미인식 / **키를 JSON에 하드코딩** / 검색 쿼리에 고객정보 삽입 → 즉시 개입.

#### 완료 판정 기준 (동작 확인)
- MCP 연결 후 실제 웹 데이터(뉴스 3건)를 가져와 화면에 표시.
- 데이터 흐름 점검표 4항목 기록 완료.
- **안전 게이트**: 키 하드코딩 0(환경변수 참조만), 쿼리에 개인정보 0.

#### 직군별 미러링 변형 (3강 공통)
| 직군 | 스킬 A(요약) | 스킬 B(정리/추출) | MCP 수집 대상 |
|------|-------------|------------------|--------------|
| 회계·세무 | 세법 개정문 요약 | 개정사항 표 추출 | 국세청·기재부 공지 |
| 법무 | 판례 핵심 요약 | 쟁점·판시 표 | 판례·입법예고 |
| 미디어 | 기사 5줄 요약 | 산업뉴스 표 | 산업 뉴스 검색 |
| MICE | 행사 개요 요약 | 행사 일정 표 | 컨퍼런스·전시 일정 |
| 투자 | 공시·리포트 요약 | 지표·이벤트 표 | 지수·종목 뉴스 |

### 실습 4-1(미니 프로젝트): 공통 프로젝트 하네스 결선 — 4역할 조립
**매핑 학습목표**: (창조) 3강 스킬·MCP를 붙여 수집·분석·검증·요약 4역할을 구성하고 하네스로 묶는다. (4-3·4-4)
**예상 소요시간**: 55분 (4-3 25분 + 4-4 30분)
**난이도**: 고급 · **피라미드 4단계(미니 프로젝트·명세서 중심)**

#### 시나리오
당신 조는 "매일 아침 글로벌 증시·주요 기업 뉴스에서 **의사결정용 브리핑**을 자동 생성"하는 에이전트팀을 만든다. 4명의 AI 직원(수집·분석·검증·요약)을 고용해 한 팀으로 일하게 하고, 버튼 한 번으로 재실행되도록 **하네스**로 포장한다.

#### 기능 요구사항
**필수(Must)**
1. **수집 에이전트**: 웹검색 MCP(3강)로 지정 주제 지수·기업 뉴스 수집.
2. **분석 에이전트**: 정리/요약 스킬(3강)로 전조·패턴·인사이트 도출.
3. **검증 에이전트**: 검증 스킬로 숫자·출처 교차검증(★ 생략 금지).
4. **요약 에이전트**: 요약 스킬로 2강 콘텐츠 포맷의 **브리핑 카드** 생성.
5. **하네스**: 위 4역할을 순서대로 재실행하는 오케스트레이션 파일 1개.

**선택(보너스)**
- 브리핑을 1강 배포 채널(페이지/DB)에 저장·게시.
- 실패 시 재시도, 주제 파라미터화(종목 목록 바꿔 실행).

#### 스캐폴딩 (스타터 명세)
> **채워둘 것**: 4개 에이전트 정의 스켈레톤(역할·입력·출력·연동 부품 슬롯) + 하네스 오케스트레이션 골격(순서·데이터 전달 배관). 실행되는 상태로 제공.
> **빈칸**: 각 에이전트의 **연동 부품 지정**(어느 스킬/MCP를 쓸지)과 **역할 프롬프트**, 하네스의 **호출 순서·전달 데이터**.

```markdown
# harness/agents/collector.md  (수집 에이전트 스켈레톤)
---
name: collector
description: 글로벌 증시·기업 뉴스 수집
tools: [web-search MCP]     # ← 3강에서 만든 MCP 지정
---
역할: __________ (빈칸: 무엇을 수집하는지)
입력: 주제/종목 목록
출력: 뉴스 원자료(제목·URL·요지) 리스트   # ← 다음(analyst)에 전달
안전: 검색 쿼리에 고객/기밀 금지
```
```markdown
# harness/agents/verifier.md  (검증 에이전트 스켈레톤 — 생략 금지 역할)
---
name: verifier
description: 숫자·출처 교차검증
tools: [verify-skill]       # ← 3강 검증 스킬
---
역할: analyst 결과의 모든 숫자·주장에 출처 확인
규칙: 출처 없는 주장은 '[미검증]' 표시 후 요약에서 제외
출력: 검증 통과 인사이트만
```
```yaml
# harness/run.yaml  (하네스 결선 골격 — 순서·전달만 채우기)
pipeline:
  - agent: collector   # 출력 → analyst.input
  - agent: analyst     # 출력 → verifier.input
  - agent: ____        # 빈칸: 무엇이 와야 하나? (검증)
  - agent: summarizer  # 출력 → 브리핑 카드
output: 내문서/vibecoding/harness/briefing_{date}.md
```

- **힌트 1(방향)**: "각 에이전트의 '출력'이 다음 에이전트의 '입력'이 되도록 배관을 잇는 게 핵심."
- **힌트 2(접근)**: "먼저 collector 하나만 돌려 뉴스가 오는지 확인 → 하나씩 뒤에 붙이세요."
- **힌트 3(골격)**: collector→analyst 2역할까지 완성본 공개 → verifier·summarizer는 조가 완성.

#### [조교 개입 신호]
- 에이전트 간 데이터가 안 넘어감 / **검증 에이전트를 건너뛰고 요약으로 직행** / 하네스가 1역할만 실행 → 즉시 개입. 특히 검증 생략은 이 강의 핵심 안전수칙이므로 반드시 잡는다.

#### 완료 판정 기준 (동작 확인)
- `run.yaml` 1회 실행 → 4역할이 순서대로 동작 → `briefing_{date}.md` 브리핑 카드 1개 생성.
- 브리핑의 모든 수치·주장에 출처가 붙어 있다(검증 에이전트 통과 증거).
- **재현성 확인**: 같은 주제로 **2회 실행** 시 동일 품질 브리핑 생성.

### 실습 4-2(캡스톤 본체): 본인 업무로 미러링
**매핑 학습목표**: (전이) 공통 하네스를 본인 I/P/O 시나리오로 복제·개조한다. (4-5)
**예상 소요시간**: 25분 (수업 내) + 30일 클리닉 정착
**난이도**: 고급 · **피라미드 5단계(캡스톤·멘토링만)**

#### 시나리오
공통 프로젝트로 원리를 익혔으니, 이제 **본인 업무(0강 I/P/O 시트 ★행)**로 하네스를 복제한다. "수집→분석→검증→요약" 4역할은 그대로, **소재·스킬·출력만 본인 업무로** 바꾼다.

#### 과제 지시
1. 0강 I/P/O 시트의 `★` 업무를 연다.
2. 공통 하네스 폴더를 복제(`harness/` → `harness_mine/`).
3. 각 에이전트의 **소재·스킬·MCP·출력**을 본인 업무로 치환(4역할 골격은 유지).
4. 본인 업무 실데이터(가명/합성)로 실행 → 결과물 1개 생성.
5. 제출물: 동작하는 `harness_mine/` + 생성 결과물 1개 + 자기판정표(4-3).

#### 스캐폴딩 (미러링 치환표 — 스타터)
> **채워둘 것**: 4역할 골격·배관은 복제 그대로 제공.
> **빈칸**: 아래 치환표의 "내 업무" 열.

```markdown
| 역할 | 공통 프로젝트 | → 내 업무로 치환 (빈칸) |
|------|--------------|------------------------|
| 수집 | 증시·뉴스 (web MCP) | ________ (내 입력원) |
| 분석 | 전조·패턴 스킬 | ________ (내 처리 규칙) |
| 검증 | 숫자·출처 검증 | ________ (내 확인 항목) |
| 요약 | 브리핑 카드 | ________ (내 출력물) |
```

- **힌트 1**: "0강 I/P/O의 입력(I)=수집, 처리(P)=분석, 출력(O)=요약에 그대로 대응돼요."
- **힌트 2**: "3강에서 만든 본인 직군 스킬을 여기에 그대로 끼우면 됩니다."
- **힌트 3**: 조교가 직군별 미러링 예(아래)로 1역할 시범 치환.

#### [조교 개입 신호]
- 미러링 대상 업무가 자동화 부적합(판단 100% 사람 몫) → 4역할 중 자동화 가능한 부분만 도려내도록 재설계 안내. / 실데이터에 고객정보 유입 → 즉시 가명화.

#### 완료 판정 기준 (동작 확인)
- `harness_mine/` 실행 → 본인 업무 결과물 1개 생성.
- 결과물이 0강 I/P/O 시트의 **출력(O)과 일치**한다.
- **재현성**: 2회 실행 동일 품질.

#### 직군별 미러링 변형 예시 (캡스톤)
| 직군 | 수집 | 분석 | 검증 | 요약(출력) |

### 실습 4-3: 루브릭 자기판정 (수료 게이트)
**매핑 학습목표**: (평가) 실데이터·결과지향·재현성 3기준으로 자기판정한다. (4-6)
**예상 소요시간**: 15분
**난이도**: 중급 · **피라미드 5단계(자기평가)**

#### 과제 지시
아래 **자기판정표**를 채워 3기준 + 안전 게이트를 스스로 판정한다. 보완 항목은 30일 클리닉으로 이월.

```markdown
[캡스톤 자기판정표]
| 기준 | 확인 질문 | 내 증거 | 통과/보완 |
|------|----------|---------|----------|
| ⓵ 실데이터 동작 | 실제 내/공통 업무 데이터로 돌았나 | ____ | ____ |
| ⓶ 결과 지향 | '응답'이 아니라 '결과물'이 나왔나 | ____ | ____ |
| ⓷ 재현성 | 2회 실행 동일 품질인가 | ____ | ____ |
[안전 게이트]
- [ ] ① 비밀키 노출 0  - [ ] ② 개인정보 입력 0  - [ ] ③ 검증 단계 수행  - [ ] ④ 데이터 흐름·최종 확인
```

#### 완료 판정 기준 (= 수료 판정)
- 3기준 **모두 통과** + 안전 게이트 4개 전부 `✅` → **수료**.
- 하나라도 보완 → 30일 클리닉에서 마무리(조건부 수료).

# 종합 평가 루브릭

## A. 캡스톤 총괄 루브릭 (수료 3기준 — AX 2차 계승, 통과/보완제)
수료의 최종 판정 기준. **3기준 모두 통과 시 수료.**

| 기준 | 통과 | 보완 (→ 30일 클리닉) |
|------|------|---------------------|
| **⓵ 실데이터 동작** | 실제 본인/공통 업무 데이터로 처음부터 끝까지 동작, 결과물 생성 | 샘플/더미로만 동작, 실데이터 미검증 |
| **⓶ 결과 지향** | "응답이 있다"가 아니라 **의사결정용 결과물**(브리핑·카드·표)이 산출됨 | 텍스트 응답만 나오고 정형 산출물 없음 |
| **⓷ 재현성** | 같은 입력 2회 실행 시 동일 품질·형식 산출 | 실행마다 형식·품질 편차 큼 |

**수료 증명** = 배포된 데모 URL(1강 부품) + 동작하는 하네스 산출 영상/기록.

## B. 안전 게이트 (전 실습 공통 — 무관용 반려제)
아래는 점수가 아니라 **게이트**다. 하나라도 위반 시 산출물 반려 후 재실행(수료 불가).

| 게이트 | 통과 조건 | 위반 예 (반려) |
|--------|----------|---------------|
| **① 비밀키 노출 0** | `anon` 공개키만 사용, `service_role`·API키가 코드·화면·스크린샷·프롬프트에 없음 | 페이지 소스/스크린샷에 service_role 노출 |
| **② 개인정보 입력 0** | 폼 예시·프롬프트·테스트에 가명/합성 데이터만 | 실제 고객명·계좌·주민번호 입력 |
| **③ 검증 단계 수행** | AI 생성 숫자·법조항·출처를 사람이 확인(2강 이후) | 검증 없이 게시, 검증 에이전트 생략 |
| **④ 데이터 흐름·최종 확인** | MCP가 데이터를 어디로 보내는지 확인, 대외 산출 전 최종 확인을 사람이 함(3강·4강) | 데이터 행선지 미확인, 사람 확인 없이 대외 발송 |

## C. 강별 실습 분석적 루브릭 (형성 — 통과선 진단용)
각 강 실습을 상/중/하로 진단해 다음 강 진입 여부·보정 필요를 판단한다.

| 강·실습 | 상 (90~100) | 중 (70~89) | 하 (0~69) |
|---------|------------|------------|----------|
| **0강 I/P/O** | 업무 2~3개 I·P·O 구체적, ★우선순위·주기 명시 | 2개 채웠으나 일부 모호 | 1개 이하·모호어 다수 |
| **1강 배포** | URL 공개 접속 + 폼 제출→Supabase 저장 확인, 확장 1개 | URL은 열리나 DB 저장 조교 도움 | URL 미배포 |
| **2강 콘텐츠** | 게시 + 검증 흔적 1건 이상 + 유튜브 세트 완비 | 게시했으나 검증 형식적 | 미검증 게시·미게시 |
| **3강 스킬·MCP** | 스킬 2~3개 트리거·동작 + MCP 실데이터 수집 | 스킬 1개 + MCP 부분 동작 | 스킬 미동작 |
| **4강 하네스** | 4역할 재실행 + 미러링 결과물 + 3기준 통과 | 공통 하네스만, 미러링 미완 | 하네스 1역할만 동작 |

- **채점 규칙**(assessment-engineering): 관찰 가능한 행동으로 기술 · 수준 간 차이 명확 · 학습자에게 사전 공개.
- **피드백 공식 EEC** 적용: 증거(Evidence) → 영향(Effect) → 변경(Change) 순으로 코멘트.

## D. 부품 이월 점검 루브릭 (조교 매 강 종료 시)
누적 부품이 다음 강으로 실제 연결되는지 확인(설계원칙 준수 검증).

| 확인 | 통과 조건 |
|------|----------|

| 1강→4강 | 배포 URL/Supabase가 하네스 출력 채널로 재사용 가능 |
| 2강→4강 | 콘텐츠 포맷이 요약 에이전트 산출 형식으로 반영 |
