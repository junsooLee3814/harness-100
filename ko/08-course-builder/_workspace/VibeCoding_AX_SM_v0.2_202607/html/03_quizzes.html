A) 구독용 웹앱 주소와 API 콘솔 주소는 같으므로 아무 데나 로그인하면 된다
B) 개인이 매달 정액으로 쓰는 구독(예: Claude Pro)과, 사용한 토큰만큼 과금되는 개발자용 API는 서로 다른 접속 경로를 쓴다
C) API는 무조건 무료이고 구독은 무조건 유료다
D) 구독을 하면 API 요금이 자동으로 0원이 된다

A

정답: B — 개인 구독(월 정액, 예: Claude Pro 약 $20/월)과 API(종량제, 토큰 과금)는 성격도 접속 주소도 다르다. 구독 웹앱(claude.ai 등)과 API 콘솔(console.anthropic.com 등)은 별개 주소.

오답 피드백:

  • D 선택 시: (E) 구독이 API를 무료화한다고 오해. (E) 둘은 별도 청구 체계입니다. (C) 구독과 API 요금은 별개.

Q1-3 [상황판단 | 블룸: 적용 | 난이도: 중]

스켈레톤(반쯤 완성된 페이지 틀)을 받아 풀스택 랜딩페이지를 만들고 실제 URL로 공개(게시)하려 합니다. 이 과정이 가르친 배포·게시 흐름의 순서로 가장 올바른 것은?

B) 자연어로 스켈레톤을 채운다 → GitHub에 코드를 올린다 → Vercel로 배포·게시해 URL을 얻는다 → Supabase에 폼 데이터를 저장한다

  • D 선택 시: (E) 페이지를 이미지로 오해. (E) 랜딩페이지는 실제 동작하는 웹페이지입니다. (C) 배포·게시는 스크린샷 업로드가 아니라 코드 게시입니다.

Q1-4 [상황판단 | 블룸: 분석 | 난이도: 중] ★ 안전수칙 필수 (anon vs service_role)

Supabase는 두 종류의 키를 줍니다: anon(공개용) 키와 service_role(비밀·전권) 키. 배포·게시한 랜딩페이지 코드에 웹에 공개되어도 되는 키는 무엇이며, 그 이유로 옳은 것은?

A) service_role 키 — 전권이 있어 어떤 기능이든 되므로 편리하다
B) 두 키 모두 넣어야 페이지가 정상 동작한다
C) anon 키 — 제한된 권한만 있어 공개를 전제로 설계된 키이기 때문
D) 어떤 키도 페이지에 넣으면 안 되고, 매번 손으로 입력해야 한다

!

정답: C — 1강 안전수칙: anon 공개키만 페이지에, service_role 키는 절대 금지. anon은 브라우저 노출 전제로 권한이 제한된 키, service_role은 DB 전권 마스터 키라 웹페이지(누구나 소스를 봄)에 넣으면 즉시 유출.

오답 피드백:

  • A 선택 시: (E) "편리하다"를 기준으로 골랐습니다. (E) 전권 키를 공개 페이지에 넣으면 누구나 DB를 삭제·탈취할 수 있습니다. (C) "공개 전제 여부"로 판단 — anon만 공개 가능.
  • B 선택 시: (E) 둘 다 필요하다고 오해. (E) service_role을 넣는 순간 전체 DB가 위험합니다. (C) 공개 페이지에는 anon 하나면 됩니다.
  • D 선택 시: (E) 아무 키도 안 넣는다고 판단. (E) anon이 없으면 폼 저장이 안 됩니다. (C) anon은 넣어도 되는 공개키입니다.

Q1-5 [짝맞추기 | 블룸: 이해 | 난이도: 중]

1강에서 배포·게시에 쓰는 3종 도구의 역할을 알맞게 연결하세요.

도구역할
① GitHub㉮ 코드를 실제 URL로 배포·게시(공개)한다

③ Supabase㉰ 폼 데이터·로그인·저장소(DB) 담당
A

정답: ① - ㉯, ② - ㉮, ③ - ㉰ — GitHub=코드 창고(저장), Vercel=배포·게시(URL 생성), Supabase=DB. 3개가 "저장→배포·게시→데이터" 한 세트.

D) 미러링은 4강 범위 밖이므로 공통 프로젝트만 제출한다

A

정답: B — 미러링 = 검증된 하네스 구조(4역할)는 재사용하고, 입력·검증 대상만 본인 업무로 치환. 원칙⓵(백지 시작 금지)·전이 목표에 부합하며, 루브릭 ⓵(실데이터 동작)을 만족시키는 길.

오답 피드백:

  • A 선택 시: (E) 이름만 바꾸는 것은 미러링이 아님. (E) 실제 회계 데이터로 동작 안 하면 루브릭 ⓵ 미충족. (C) 입력·처리·검증을 본인 업무에 맞게 실제로 바꾸세요.
  • C 선택 시: (E) 부품을 버리고 백지로 감. (E) 원칙⓵ 위반이며 시간 낭비. (C) 검증된 구조를 재사용하고 내용만 치환.
  • D 선택 시: (E) 미러링을 범위 밖으로 오해. (E) 미러링(4-5)은 과정의 핵심 목표(전이). (C) 본인 업무 버전까지 만들어야 수료 취지에 맞음.
