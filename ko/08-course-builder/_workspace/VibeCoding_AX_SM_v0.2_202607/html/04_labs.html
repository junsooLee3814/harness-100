0.1 3대 설계원칙 준수 방식

원칙 본 실습설계 반영 방식
⓵ 백지 시작 금지 모든 실습에 스타터 파일(스켈레톤/템플릿/프롬프트 카드)를 배포한다. 학습자는 "채우기 → 고치기 → 확장하기"만 한다. 빈 화면·빈 파일에서 시작하라는 지시는 없다.
⓶ 데모 먼저 각 실습 시작 시 완성 산출물(참조본)을 먼저 제시한다. 학습자는 "무엇이 나오는지" 눈으로 본 뒤 손을 움직인다. 참조본은 조교가 미리 배포/실행해 둔다.
⓷ 강사+조교 배석 각 실습에 [조교 개입 신호]를 명시했다. 3인 1조 중 한 명이 막히면 조 전체가 멈추므로, 신호 발생 시 조교가 즉시 개입한다.

강 실습 피라미드 단계 학습자 자율성 스타터 형태

2강 콘텐츠 엔진 2→3 (가이드→챌린지) 40% 프롬프트 템플릿(빈칸) + 검증 체크리스트

4강 하네스 캡스톤 4→5 (미니→캡스톤) 80~95% 4역할 에이전트 스켈레톤 + 하네스 결선 골격

0강 도구 10종 체크리스트 스크린샷 폴더 1~4강 환경 선수조건

0.5 안전 게이트 (전 실습 공통 — 위반 시 산출물 반려)

모든 실습은 제출 전 아래 4게이트를 자기점검 체크박스로 통과해야 한다. 하나라도 위반 시 반려 후 재실행.

  • ① 비밀키 노출 0: service_role·API 키·토큰이 코드·화면·스크린샷·프롬프트 어디에도 없다. (공개키 anon만 허용)
  • ② 고객/개인정보 입력 0: 실명·주민번호·계좌·연락처·고객 식별정보를 폼 예시·프롬프트·테스트 데이터에 넣지 않았다. (합성/가명 데이터만)
  • ③ 검증 단계 수행: AI 생성 숫자·법조항·출처를 사람이 확인했다. (2강 이후 필수)
  • ④ 데이터 흐름·최종 확인: MCP가 데이터를 어디로 보내는지 확인했고, 대외 산출 전 최종 확인을 사람이 했다. (3강·4강)

시나리오

당신은 선명AG 정규직이며 코딩 경험이 전혀 없다. 본과정 첫 실습(1강 배포)에 들어가려면 그 전에 "연장"부터 손에 쥐어야 한다. 가이드 영상을 보며 계정·설치를 그대로 따라 완료한다.

과제 지시

  1. 배포된 체크리스트 워크시트(아래 스타터)를 연다.

  4. 제출물: 완료된 체크리스트 + 증거 스크린샷 폴더.

스캐폴딩 (스타터 명세)

채워둘 것: 항목·순서·확인 명령어·안전 경고가 이미 적힌 워크시트. 빈칸: [완료✅/미완❌] 상태칸과 증거 링크칸만 학습자가 채운다.

실습 3-2: MCP 연결 — 외부 데이터 가져오기 (★ 부품: MCP 설정)

매핑 학습목표: (적용) MCP를 연결해 외부 데이터를 가져온다. (3-5) 예상 소요시간: 25분 난이도: 중급 · 피라미드 3단계

시나리오

스킬이 "내가 만든 도구"라면 MCP는 "외부 세계로 난 창"이다. 웹검색 MCP를 연결해 실시간 뉴스·지수를 가져온다. 이 연결은 4강 수집 에이전트의 손발이 된다. 동시에 "이 데이터가 어디로 가는지" 확인하는 안전 습관을 익힌다.

과제 지시

  1. 시연에서 MCP가 실시간 데이터를 물어오는 장면 관찰(⓶).
  2. MCP 설정 스니펫(스타터)의 빈칸을 채워 웹검색 MCP를 연결.
  3. 연결 후 "오늘 나스닥/코스피 주요 뉴스 3건 가져와" 등으로 실데이터 수집 테스트.
  4. 데이터 흐름 점검: 이 MCP가 무엇을 어디로 보내는지 1줄로 기록.
  5. 제출물: 동작하는 .mcp.json + 수집 테스트 결과 캡처.

스캐폴딩 (스타터 명세)

채워둘 것: MCP 설정 JSON 구조 + 서버 이름 슬롯. 빈칸: 사용할 MCP 서버 지정, (필요 시) 키는 환경변수 참조로만.

// .mcp.json  (스타터: 서버명·env 참조만 채우기. 키를 직접 붙여넣지 말 것)
{

    "web-search": {
      "command": "____",           // 빈칸: 웹검색 MCP 실행 명령
      "args": [],
      "env": { "SEARCH_API_KEY": "${SEARCH_API_KEY}" }  // ⚠️ 값이 아니라 참조!
    }
  }
}

- 보내는 곳: (예) 검색 제공자 서버
- 받아오는 것: (예) 뉴스 제목·URL·요약
- 고객/기밀 정보를 쿼리에 넣지 않는다: [ ] 확인
  • 힌트 1: "MCP는 설정 후 Claude Code 재시작해야 잡혀요." · 힌트 2: "키는 절대 JSON에 직접 X → ${환경변수} 참조."
  • 힌트 3: 동작하는 최소 설정 1개 공개.

[조교 개입 신호]

  • MCP 미인식 / 키를 JSON에 하드코딩 / 검색 쿼리에 고객정보 삽입 → 즉시 개입.

완료 판정 기준 (동작 확인)

  • MCP 연결 후 실제 웹 데이터(뉴스 3건)를 가져와 화면에 표시.
  • 데이터 흐름 점검표 4항목 기록 완료.
  • 안전 게이트: 키 하드코딩 0(환경변수 참조만), 쿼리에 개인정보 0.

4강 캡스톤 — "부품을 팀으로, 팀을 하네스로" (총괄평가)

캡스톤 개요

전 과정의 부품을 집결시켜 글로벌 증시·뉴스 인사이트 에이전트팀 하네스를 완성하고, 이를 본인 업무로 미러링한다. 이것이 수료 증거물이다.

[캡스톤 부품 집결도]
0강 I/P/O 시트 ─────────────────────────▶ (4-3 미러링 시드)
1강 배포 URL/Supabase ──┐
2강 콘텐츠 포맷 ─────────┤─▶ 4역할 에이전트팀 ─▶ 하네스 1개 ─▶ 본인 업무 미러링
3강 스킬 2~3 + MCP ─────┘   (수집·분석·검증·요약)   (재실행)    (전이)

학습목표 매핑 (이 캡스톤이 통합 평가하는 것)

  • LO3(창조): 4역할 에이전트를 하나의 팀으로 오케스트레이션. (4-3·4-4)
  • LO3(창조): 재실행 가능한 하네스로 패키징. (4-4)
  • LO4(전이): 공통 프로젝트를 본인 업무로 미러링. (4-5)
  • LO5(평가): 산출물을 수료 루브릭 3기준으로 자기판정. (4-6)

실습 4-1(미니 프로젝트): 공통 프로젝트 하네스 결선 — 4역할 조립

매핑 학습목표: (창조) 3강 스킬·MCP를 붙여 수집·분석·검증·요약 4역할을 구성하고 하네스로 묶는다. (4-3·4-4) 예상 소요시간: 55분 (4-3 25분 + 4-4 30분) 난이도: 고급 · 피라미드 4단계(미니 프로젝트·명세서 중심)

시나리오

당신 조는 "매일 아침 글로벌 증시·주요 기업 뉴스에서 의사결정용 브리핑을 자동 생성"하는 에이전트팀을 만든다. 4명의 AI 직원(수집·분석·검증·요약)을 고용해 한 팀으로 일하게 하고, 버튼 한 번으로 재실행되도록 하네스로 포장한다.

기능 요구사항

필수(Must)

  1. 수집 에이전트: 웹검색 MCP(3강)로 지정 주제 지수·기업 뉴스 수집.
  2. 분석 에이전트: 정리/요약 스킬(3강)로 전조·패턴·인사이트 도출.
  3. 검증 에이전트: 검증 스킬로 숫자·출처 교차검증(★ 생략 금지).
  4. 요약 에이전트: 요약 스킬로 2강 콘텐츠 포맷의 브리핑 카드 생성.
  5. 하네스: 위 4역할을 순서대로 재실행하는 오케스트레이션 파일 1개.

선택(보너스)

  • 브리핑을 1강 배포 채널(페이지/DB)에 저장·게시.
  • 실패 시 재시도, 주제 파라미터화(종목 목록 바꿔 실행).

스캐폴딩 (스타터 명세)

채워둘 것: 4개 에이전트 정의 스켈레톤(역할·입력·출력·연동 부품 슬롯) + 하네스 오케스트레이션 골격(순서·데이터 전달 배관). 실행되는 상태로 제공. 빈칸: 각 에이전트의 연동 부품 지정(어느 스킬/MCP를 쓸지)과 역할 프롬프트, 하네스의 호출 순서·전달 데이터.

# harness/agents/collector.md  (수집 에이전트 스켈레톤)
---
name: collector
description: 글로벌 증시·기업 뉴스 수집
tools: [web-search MCP]     # ← 3강에서 만든 MCP 지정
---
역할: __________ (빈칸: 무엇을 수집하는지)
입력: 주제/종목 목록
출력: 뉴스 원자료(제목·URL·요지) 리스트   # ← 다음(analyst)에 전달
안전: 검색 쿼리에 고객/기밀 금지

# harness/agents/verifier.md  (검증 에이전트 스켈레톤 — 생략 금지 역할)
---
name: verifier
description: 숫자·출처 교차검증
tools: [verify-skill]       # ← 3강 검증 스킬
---
역할: analyst 결과의 모든 숫자·주장에 출처 확인
규칙: 출처 없는 주장은 '[미검증]' 표시 후 요약에서 제외
출력: 검증 통과 인사이트만

# harness/run.yaml  (하네스 결선 골격 — 순서·전달만 채우기)
pipeline:

  - agent: collector   # 출력 → analyst.input
  - agent: analyst     # 출력 → verifier.input
  - agent: ____        # 빈칸: 무엇이 와야 하나? (검증)
  - agent: summarizer  # 출력 → 브리핑 카드
output: 내문서/vibecoding/harness/briefing_{date}.md
  • 힌트 1(방향): "각 에이전트의 '출력'이 다음 에이전트의 '입력'이 되도록 배관을 잇는 게 핵심."
  • 힌트 2(접근): "먼저 collector 하나만 돌려 뉴스가 오는지 확인 → 하나씩 뒤에 붙이세요."
  • 힌트 3(골격): collector→analyst 2역할까지 완성본 공개 → verifier·summarizer는 조가 완성.

[조교 개입 신호]

  • 에이전트 간 데이터가 안 넘어감 / 검증 에이전트를 건너뛰고 요약으로 직행 / 하네스가 1역할만 실행 → 즉시 개입. 특히 검증 생략은 이 강의 핵심 안전수칙이므로 반드시 잡는다.

완료 판정 기준 (동작 확인)

  • run.yaml 1회 실행 → 4역할이 순서대로 동작 → briefing_{date}.md 브리핑 카드 1개 생성.
  • 브리핑의 모든 수치·주장에 출처가 붙어 있다(검증 에이전트 통과 증거).
  • 재현성 확인: 같은 주제로 2회 실행 시 동일 품질 브리핑 생성.

실습 4-2(캡스톤 본체): 본인 업무로 미러링

매핑 학습목표: (전이) 공통 하네스를 본인 I/P/O 시나리오로 복제·개조한다. (4-5) 예상 소요시간: 25분 (수업 내) + 30일 클리닉 정착 난이도: 고급 · 피라미드 5단계(캡스톤·멘토링만)

시나리오

공통 프로젝트로 원리를 익혔으니, 이제 본인 업무(0강 I/P/O 시트 ★행)로 하네스를 복제한다. "수집→분석→검증→요약" 4역할은 그대로, 소재·스킬·출력만 본인 업무로 바꾼다.

과제 지시

  1. 0강 I/P/O 시트의 ★ 업무를 연다.
  2. 공통 하네스 폴더를 복제(harness/ → harness_mine/).
  3. 각 에이전트의 소재·스킬·MCP·출력을 본인 업무로 치환(4역할 골격은 유지).
  4. 본인 업무 실데이터(가명/합성)로 실행 → 결과물 1개 생성.
  5. 제출물: 동작하는 harness_mine/ + 생성 결과물 1개 + 자기판정표(4-3).

스캐폴딩 (미러링 치환표 — 스타터)

채워둘 것: 4역할 골격·배관은 복제 그대로 제공. 빈칸: 아래 치환표의 "내 업무" 열.

| 역할 | 공통 프로젝트 | → 내 업무로 치환 (빈칸) |
|------|--------------|------------------------|
| 수집 | 증시·뉴스 (web MCP) | ________ (내 입력원) |
| 분석 | 전조·패턴 스킬 | ________ (내 처리 규칙) |

  • 힌트 1: "0강 I/P/O의 입력(I)=수집, 처리(P)=분석, 출력(O)=요약에 그대로 대응돼요."
  • 힌트 2: "3강에서 만든 본인 직군 스킬을 여기에 그대로 끼우면 됩니다."
  • 힌트 3: 조교가 직군별 미러링 예(아래)로 1역할 시범 치환.

[조교 개입 신호]

  • 미러링 대상 업무가 자동화 부적합(판단 100% 사람 몫) → 4역할 중 자동화 가능한 부분만 도려내도록 재설계 안내. / 실데이터에 고객정보 유입 → 즉시 가명화.

완료 판정 기준 (동작 확인)

  • harness_mine/ 실행 → 본인 업무 결과물 1개 생성.
  • 결과물이 0강 I/P/O 시트의 출력(O)과 일치한다.
  • 재현성: 2회 실행 동일 품질.

실습 4-3: 루브릭 자기판정 (수료 게이트)

매핑 학습목표: (평가) 실데이터·결과지향·재현성 3기준으로 자기판정한다. (4-6) 예상 소요시간: 15분 난이도: 중급 · 피라미드 5단계(자기평가)

과제 지시

아래 자기판정표를 채워 3기준 + 안전 게이트를 스스로 판정한다. 보완 항목은 30일 클리닉으로 이월.

|------|----------|---------|----------|
| ⓵ 실데이터 동작 | 실제 내/공통 업무 데이터로 돌았나 | ____ | ____ |

| ⓷ 재현성 | 2회 실행 동일 품질인가 | ____ | ____ |
[안전 게이트]

- [ ] ① 비밀키 노출 0  - [ ] ② 개인정보 입력 0  - [ ] ③ 검증 단계 수행  - [ ] ④ 데이터 흐름·최종 확인

완료 판정 기준 (= 수료 판정)

  • 3기준 모두 통과 + 안전 게이트 4개 전부 ✅ → 수료.
  • 하나라도 보완 → 30일 클리닉에서 마무리(조건부 수료).
종합 평가 루브릭
08
A. 캡스톤 총괄 루브릭 (수료 3기준 — AX 2차 계승, 통과/보완제)

수료의 최종 판정 기준. 3기준 모두 통과 시 수료.

기준 통과 보완 (→ 30일 클리닉)
⓵ 실데이터 동작 실제 본인/공통 업무 데이터로 처음부터 끝까지 동작, 결과물 생성 샘플/더미로만 동작, 실데이터 미검증
⓶ 결과 지향 "응답이 있다"가 아니라 의사결정용 결과물(브리핑·카드·표)이 산출됨 텍스트 응답만 나오고 정형 산출물 없음
⓷ 재현성 같은 입력 2회 실행 시 동일 품질·형식 산출 실행마다 형식·품질 편차 큼

수료 증명 = 배포된 데모 URL(1강 부품) + 동작하는 하네스 산출 영상/기록.

09
B. 안전 게이트 (전 실습 공통 — 무관용 반려제)

아래는 점수가 아니라 게이트다. 하나라도 위반 시 산출물 반려 후 재실행(수료 불가).

게이트 통과 조건 위반 예 (반려)
① 비밀키 노출 0 anon 공개키만 사용, service_role·API키가 코드·화면·스크린샷·프롬프트에 없음 페이지 소스/스크린샷에 service_role 노출
② 개인정보 입력 0 폼 예시·프롬프트·테스트에 가명/합성 데이터만 실제 고객명·계좌·주민번호 입력
③ 검증 단계 수행 AI 생성 숫자·법조항·출처를 사람이 확인(2강 이후) 검증 없이 게시, 검증 에이전트 생략
④ 데이터 흐름·최종 확인 MCP가 데이터를 어디로 보내는지 확인, 대외 산출 전 최종 확인을 사람이 함(3강·4강) 데이터 행선지 미확인, 사람 확인 없이 대외 발송
10
C. 강별 실습 분석적 루브릭 (형성 — 통과선 진단용)

각 강 실습을 상/중/하로 진단해 다음 강 진입 여부·보정 필요를 판단한다.

강·실습 상 (90~100) 중 (70~89) 하 (0~69)
0강 I/P/O 업무 2~3개 I·P·O 구체적, ★우선순위·주기 명시 2개 채웠으나 일부 모호 1개 이하·모호어 다수
1강 배포 URL 공개 접속 + 폼 제출→Supabase 저장 확인, 확장 1개 URL은 열리나 DB 저장 조교 도움 URL 미배포
2강 콘텐츠 게시 + 검증 흔적 1건 이상 + 유튜브 세트 완비 게시했으나 검증 형식적 미검증 게시·미게시
3강 스킬·MCP 스킬 2~3개 트리거·동작 + MCP 실데이터 수집 스킬 1개 + MCP 부분 동작 스킬 미동작
4강 하네스 4역할 재실행 + 미러링 결과물 + 3기준 통과 공통 하네스만, 미러링 미완 하네스 1역할만 동작
  • 채점 규칙(assessment-engineering): 관찰 가능한 행동으로 기술 · 수준 간 차이 명확 · 학습자에게 사전 공개.
  • 피드백 공식 EEC 적용: 증거(Evidence) → 영향(Effect) → 변경(Change) 순으로 코멘트.
11
D. 부품 이월 점검 루브릭 (조교 매 강 종료 시)

누적 부품이 다음 강으로 실제 연결되는지 확인(설계원칙 준수 검증).

확인 통과 조건
0강→4강 I/P/O 시트가 저장돼 4강 미러링에 로드됨
1강→4강 배포 URL/Supabase가 하네스 출력 채널로 재사용 가능
2강→4강 콘텐츠 포맷이 요약 에이전트 산출 형식으로 반영
3강→4강 스킬 파일·MCP 설정이 4역할 에이전트에 실제 연결
