# Calc Verify — 계산 사례 기계 검산 엔진

**교재의 계산 오류는 오탈자가 아니라 사고다** — 독자가 그 숫자로 의사결정을 한다. LLM이 만든 계산을 같은 LLM이 눈으로 검산하는 것은 검산이 아니다. 이 엔진이 기계로 거른다.

## 사용법

```bash
PY="C:/Users/<user>/AppData/Local/Programs/Python/Python312/python.exe"
$PY .claude/skills/calc-verify/verify_calc.py _workspace/{법률명}/04_examples/{장번호}_{주제}/cases.json
```

| exit | 의미 | 조치 |
|:-:|---|---|
| 0 | 전 사례 통과 | 납품 가능 |
| 1 | 입력 오류 (파일·JSON·cases 누락) | 입력 수정 |
| 2 | **검산 불일치** | 본문 수치 또는 사례 정정 — 불일치 상태 납품 절대 금지 |
| 3 | 경고 (기준연도·본문_표기값 누락) | 보완. 불가피하면 `--allow-warnings` + 사유 |

## cases.json 구조 — 견본: `cases.sample.json`

```json
{"cases": [{
  "id": "상속세_기본_일괄공제",
  "desc": "한 줄 상황",
  "기준연도": "2026 (확인값 출처 명시)",          ← 누락 시 경고 (세율은 연도의 함수다)
  "inputs": {"상속재산": 1200000000, "일괄공제": 500000000},
  "steps": [
    {"name": "과세표준", "expr": "상속재산 - 일괄공제", "expected": 700000000},
    {"name": "산출세액",
     "누진세율": {"base": "과세표준",
       "brackets": [[100000000, 0.10, 0], [500000000, 0.20, 10000000],
                    [1000000000, 0.30, 60000000], [3000000000, 0.40, 160000000],
                    [null, 0.50, 460000000]]},   ← [상한, 세율, 누진공제], 마지막 상한 null
     "expected": 150000000}
  ],
  "최종단계": "산출세액",
  "본문_표기값": 150000000                        ← 교재 본문에 인쇄될 바로 그 숫자
}]}
```

- `expr`: 산술식. 앞 단계의 `name`을 변수로 사용 가능. 허용: `+ - * / // % **`, `min max round abs int`, 비교, `a if 조건 else b`
- `누진세율`: 세율 구간표 전용 헬퍼 — 방식은 "구간 세율 × 과세표준 − 누진공제"
- `tolerance`: 허용 오차 (기본 0 — 원 단위 정확 일치). **기대값의 0.1% 초과 tolerance는 경고(exit 3)** — 오차 은폐 방지. 통과 시에도 `(tol=N 적용)` 표시가 출력돼 검증자 재실행에서 보인다

## 안전 설계

- **eval/exec 미사용** — AST 화이트리스트 평가기. 함수 호출·임포트·문자열 연산은 거부된다 (주입 시험 통과)
- brackets의 세율·공제값은 **law-researcher가 확인한 값만** 사용 — 엔진은 산수를 검사하지, 세법을 검사하지 않는다

## 워크플로우 위치

1. example-builder: 사례 설계 → cases.json 작성 → **exit 0 확인 후** example.md 납품
2. chapter-writer: 검산 통과 사례만 본문에 삽입
3. textbook-reviewer: 장 검증 시 **재실행** — 통과 로그를 검증 보고서에 첨부

## 한계 (알고 쓸 것)

- 산수 검산이지 **법 해석 검산이 아니다** — 공제 적용 순서·안분 같은 로직 오류는 steps 설계 자체가 틀리면 못 잡는다. 검증자의 6축 검증과 최종 전문가 감수가 그 층을 맡는다
- 세율표가 옛 값이면 검산이 통과해도 틀린 사례다 — `기준연도` + legal-currency-guard 확인이 전제
