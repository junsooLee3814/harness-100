## §0. 절대 규칙 (위반 시 반려)

1. **하위 에이전트를 띄우지 마라.** 검색·확인은 직접·짧게 한다.
   1·2호기에서 집필자가 검증 서브에이전트를 띄우고 그 결과를 기다리며 멈춰 선 사고가 5건 이상 났다.
2. **조사에 없는 조문번호·수치·사건번호를 본문에 쓰지 마라** (헌법 2조).
   미확정은 **법리만 서술 + `[검증필요 — 무엇이 미확정인지]`** 로 남기고 **진행한다.**
   확인될 때까지 대기하지 않는다.
3. **계산 사례는 `verify_calc.py`를 통과하기 전에는 본문에 넣지 않는다** (헌법 3조).
4. **분량은 밴드다** — `하한 ~ 상한(=하한×1.15)`. 하한 미달·상한 초과 모두 반려.
   상한 초과 시 §5 순위대로 삭감한 뒤 제출한다.
5. **종결어미는 서술체(~이다 / ~한다).** 청유·권유·명령·경어형(`~하자·~바란다·~하라·~하세요`) 금지.
6. **한 사실은 가장 적합한 한 곳에서만 말하라.** 2호기 분량 폭주(3.3배)의 실제 원인이 중복 서술이었다.

## §2-1. 제14·15장 재편 — 납세의무자로 자른다 (2판 변경사항)

| 장 | 제목 | 납세의무자 | 담는 것 |
|:--:|---|---|---|
| **14** | **조합의 회계·세무와 비용 투명성** | **조합(법인)** | **구분경리**(조합원분/일반분양분) · 법인세 · 부가가치세 · 원천세<br>+ 예산·자금 차입 · 회계감사 · 정보공개 · 공사비 검증(기존 유지)<br>※ 「정비사업조합 회계기준 고시」는 **존재하지 않는다**(아래 ① 참조) |

### ★ 교열 여유분 — 집필·압축은 상한의 97%를 겨냥한다

**문체 교열(Phase 5)은 분량을 늘린다.** 1판 실측에서 19파일 전부가 늘었다(100.7% ~ 104.5%, 평균 약 102%).
고유어 서사를 한자어 개념어로 격상하면 글자 수가 증가하는 것이 정상이다.

따라서 **집필·압축 단계의 실질 목표는 `상한 × 0.97`**이다. 상한에 딱 붙여 끝내면 교열에서 반드시 넘긴다.

**⚠️ 다만 이 97% 목표는 「어차피 압축하는 장」에만 적용한다.**
이미 밴드 안에 든 장을 3% 깎았다가 교열에서 2% 되돌리는 것은 헛수고다. 규칙은 이렇게 갈린다.

|---|---|

| **밴드 내, 상한 여유 3% 이상** | 그대로 둔다 |
| **밴드 내, 상한 여유 3% 미만** | 그대로 두되 **교열 단계에서 「글자수 중립 교체」를 원칙**으로 삼는다.<br>어휘를 격상하되 늘어난 만큼 다른 곳에서 줄여 총량을 유지한다 |

**교열자에게 넘기는 지시** — 상한 여유가 3% 미만인 장은 파일 머리에 그 사실이 기록돼 있다.

| **[원문 확인]** | 국가법령정보센터·판례 원문을 직접 확인 | 조문번호·수치·사건번호 인용 가능 |
| **[복수 출처]** | 원문 미확인, 신뢰 가능한 2곳 이상 일치 | 인용 가능하되 `[검증필요]` 병기 |
| **[미확정]** | 미조회·출처 불일치 | **법리만 서술.** 번호·수치 금지 + `[검증필요]` |

`[검증필요]`는 감수자에게 넘기는 작업 지시다. **개수를 줄이는 것이 목적이 아니라 정확히 남기는 것이 목적**이다.
다만 2판에서는 **조회하면 끝나는 것(조문번호·시행일·사건번호)은 조사 단계에서 해소한다** — 현재 73건 중 상당수가 그렇다.

## §8. 계산 사례 규격

장별 폴더로 분리한다. **공유 파일을 병렬로 쓰면 충돌한다.**

```
04_examples/{NN}_{주제}/cases.json   ← 기계 검산 입력
04_examples/{NN}_{주제}/example.md  ← 본문 전재용 풀이
```

`cases.json`은 `inputs` + `steps` 구조이며, 형식은 `.claude/skills/calc-verify/cases.sample.json`을 따른다.
검산 명령:

```bash
PY="C:/Users/juncp/AppData/Local/Programs/Python/Python312/python.exe"
PYTHONUTF8=1 $PY .claude/skills/calc-verify/verify_calc.py "_workspace/도정법/04_examples/{폴더}/cases.json"
```

**세트 구성** — 한 주제당 `표준 → 변형 → 함정 → 경계값` 순으로 쌓는다.
함정 사례는 §3의 함정 11개와 연결한다(예: 동의율에서 공유 지분을 1인으로 세는 오류).

**면책** — 모든 계산 사례에 「가상 수치이며 실제 사업에는 개별 확인이 필요하다」는 취지의 문구를 붙인다.

### ★ `example.md`는 원자재이지 완제품이 아니다 — 집필자 주의

`example.md`는 **사례를 넉넉히 담은 재료 창고**다. E1 실측에서 4장 `example.md`의 전재 가능 본문이
**10,809자**로 나왔는데 4장 밴드는 12,800~14,720자다. **통째로 옮기면 나머지 5블록이 들어갈 자리가 없다.**

**집필자는 전재하지 말고 선별·압축한다.**

1. **표와 검산 통과 수치는 그대로 옮긴다** — §5 삭감 금지 대상이다
2. **설명 산문은 압축한다** — 창고의 서술은 자세할수록 좋게 쓰여 있으나, 본문에서는 5블록의
   다른 요소와 자리를 나눠야 한다
3. **전 사례를 다 넣지 않아도 된다** — 표준·함정·경계값을 대표로 살리고 변형은 표 한 행으로 접는다
4. **최종 판정 기준은 장 밴드다.** 사례를 다 넣어 상한을 넘기면 반려다

`cases.json`의 **모든** case가 본문에 나와야 하는 것은 아니다. 다만 **본문에 쓴 숫자는 반드시
검산을 통과한 case의 값**이어야 한다 — 본문에서 새 숫자를 만들어내면 안 된다.
