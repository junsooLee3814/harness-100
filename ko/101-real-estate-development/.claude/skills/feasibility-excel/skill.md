# Feasibility Excel — 사업수지 워크북 생성 엔진

**값이 아니라 수식을 기입한다.** 사용자가 `00_입력` 시트의 노란 셀(분양가·공사비·금리 등)을 바꾸면 사업이익·비례율·피크자금이 전부 자동 재계산된다. 이것이 이 엔진의 존재 이유다.

> 설계 근거: `_design/excel_schema.md` — 실제 대주 제출용 PF 금융모델을 분해해 확정한 스키마

---

## 사용법

```bash
python .claude/skills/feasibility-excel/build_xlsx.py <config.json> <output.xlsx>
```

Windows에서 시스템 Python을 명시해야 할 수 있다 (가상환경에 openpyxl이 없는 경우):
```bash
"C:/Users/<user>/AppData/Local/Programs/Python/Python312/python.exe" build_xlsx.py config.json out.xlsx
```

출력 예 (민간 자체시행 — 6시트):
```
OK: C:/.../사업수지_○○사업_20260728.xlsx
sheets=6 : 00_입력, 01_사업수지, 02_현금흐름, 03_민감도, 04_요약, 05_검증
broken_refs=0
warnings=0
```
정비사업이면 `06_비례율`이 추가되어 7시트가 된다.

### 종료 코드 — 반드시 확인할 것

| 코드 | 의미 | 조치 |
|:-:|---|---|
| 0 | 정상 | 진행 |
| 1 | config 스키마 오류 (필수 블록·revenue 누락 등) | config 수정 후 재실행 |
| 2 | 깨진 참조 발견 (`broken_refs > 0`) | 버그. 산출물 사용 금지 |
| 3 | **경고 발생** (배분율·공정률 합계, 기간 상한 초과, PF이자 항목 누락, 비용 그룹 누락) | config 수정 후 재실행 |

경고를 알면서 진행해야 한다면 `--allow-warnings` 를 붙이고 **보고서에 사유를 반드시 명시**한다. 경고를 침묵시키려고 습관적으로 붙이지 않는다.

## config.json 작성 규칙

견본: `config.sample.json`(민간 자체시행) / `config.jeongbi.sample.json`(정비사업)

### 필수 블록

| 블록 | 내용 |
|---|---|
| `project` | name · type · location · date |
| `site` | 대지면적_m2 · 지상연면적_m2 · 지하연면적_m2 · 건폐율 · 용적률 · 세대수 · 주차대수 |
| `period` | 인허가_개월 · 공사_개월 · 분양정산_개월 · **지연버퍼_개월** |
| `revenue[]` | 구분 · 세부 · 분양면적_평 · 평당분양가_천원 · 근거 |
| `cost` | 토지비 / 건축비 / 부대비용 / 금융비용 각 배열 |
| `funding` | equity_천원 · tranches[] (구분·인출방식·한도_천원·금리·취급수수료) |
| `schedule` | 총개월 · 공정률[] · 분양률[] · 납입{} |
| `jeongbi` | (정비사업만) 종전자산_천원 · 조합원수 · 조합원분양가_천원 |

> ⚠️ `jeongbi.토지비제외` 는 **폐기된 키**입니다. 그룹 단위로 토지비 전체를 총사업비에서 빼던 방식으로, 현금청산금·주거이전비 같은 실제 현금지출까지 제외해 비례율을 과대 산출시켰습니다. 지금은 **항목 단위 `"비례율제외": true`** 로 대체되었고, 이 키를 넣으면 무시되며 경고가 발생합니다.

### 지출 항목 작성

```json
{"항목": "직접공사비", "산출근거": "연면적(평)", "수량": 4990, "단가": 6500,
 "신뢰도": "[가정] 업계 참고단가", "필수비율": 0.9, "준공후불비율": 0.1}
```

- `수량` + `단가`를 주면 **`=수량×단가` 수식**이 들어간다 (권장 — 사용자가 단가만 바꿔 재계산 가능)
- 총액만 알면 `금액_천원`을 준다
- `신뢰도`에 근거 수준을 반드시 기재한다 — `계약서` / `견적` / `법정요율` / `관행` / `[가정] …`
- `기투입_천원`은 이미 집행한 Equity 금액

### 배분율 3종 — 합계 = 1

```
필수비율 + 분양불비율 + 준공후불비율 = 1.0
```

- `필수비율`을 생략하면 `1 − 분양불 − 준공후불`로 자동 산정된다
- 합계가 1이 아니면 `[WARN]`이 뜨고 `05_검증` 시트의 자금집행 균형이 **불일치**로 표시된다
- 통상값: 토지비·수수료 `필수 1.0` / 공사비 `필수 0.9, 준공후불 0.1` / 분양대행·광고 `분양불 1.0`

### 드라이버 배열 — 합계 = 1

- `공정률[]` 합계는 **정확히 1.0**이어야 한다. 아니면 건축비 월별 배분이 총액과 어긋나 검증 열이 "불일치"를 낸다
- `분양률[]` 합계가 1 미만이면 그만큼 **사업기간 내 미회수**가 발생한다. 엔진이 경고하고 `05_검증`이 "미회수 발생"으로 표시한다 — 이는 오류가 아니라 **의도한 미분양 시나리오일 수 있으므로 보고서에 반드시 설명**한다
- 길이는 `총개월`과 맞춘다

| `03_민감도` | 분양가 × 공사비 2변수 표 · **분양률 민감도(100/90/80/70%)** · **손익분기 분양률** · 손익분기 평당분양가 |
| `04_요약` | 총사업기간 · 수입 · 지출 · 사업이익률 · 금융비용 · 피크자금 · 현금 최저점 · 한도초과 여부 · **LTV · LTC** |
| `05_검증` | 6개 정합성 체크 (전부 통과해야 산출물 제출 가능) |

## 엔진이 자동으로 하는 일

### 1. PF이자 자동 연결
금융비용에 `PF이자` 항목이 있으면, 그 금액을 **`02_현금흐름`의 월별 이자 합계로 자동 치환**한다.
config에 적은 임시 이자값은 무시된다. 실제 PF 모델과 동일한 역참조 구조이며, 현금흐름의 지출에는 금융비용이 포함되지 않으므로 **순환참조가 발생하지 않는다.**

> 실측 효과: 샘플에서 config의 임시 이자(31억)가 실제 계산값(54억)으로 치환되면서 사업이익이 42억 → 18.5억으로 정정되었다. **이자 과소계상은 가장 흔한 낙관 편향이다.**

### 2. 자동 인출 (한도대출 로직)
매월 현금이 마이너스로 떨어지면 그 부족분만큼 PF를 자동 인출한다.
```
인출 = MAX(0, -(전월현금 + 수입 - 지출 - 이자 - 상환))
```
그 결과 **현금 최저점은 0**이 되고, 실제 조달 소요는 **PF 잔액 최대치(피크자금)**로 나타난다.

### 3. 비례율 총사업비에서 현물출자분 제외 ★ 항목 단위
비례율 = (종후자산 − 총사업비) ÷ 종전자산 에서, **총사업비에 조합원이 현물출자한 종전자산(토지)이 들어가면 이중계상**이 되어 비례율이 과소 산출된다.

- 제외 대상은 **조합원 현물출자분 그 자체뿐**이다. 해당 지출 항목에 `"비례율제외": true` 를 붙인다
- **현금청산금·국공유지 매입비·주거이전비·영업손실보상은 실제 현금지출이므로 제외하지 않는다.** 이것들까지 빼면 비례율이 20%p 이상 과대 산출된다
- 그룹(토지비 전체) 단위 제외은 지원하지 않는다 — 위 오류를 유발하기 때문이다
- 제외한 항목은 `01_사업수지` 신뢰도 열에 `[비례율 제외]` 태그가 붙고, `06_비례율` 시트에 항목명이 표시된다

## 산출 후 필수 검증

1. `broken_refs=0` 확인 (종료 코드 0)
2. `[WARN]` 없음 확인 — 있으면 config 수정 후 재생성
3. `05_검증` 시트 6개 항목 전부 통과 확인
4. `02_현금흐름` 맨 오른쪽 **검증 열에 "불일치" 0건** 확인
5. 엑셀에서 실제로 열리는지 확인

**정합성 검증 6개 항목**
- 자금집행 균형 (예산 = 기투입+필수+분양불+준공후불)
- 사업이익 부호 (적자면 재검토 판정)
- 현금 부족 발생 여부
- PF 한도 내 조달 가능
- 손익분기 분양률 < 100%
- 수지표 수입 = 현금흐름 회수액

## 구현 범위와 한계 ★ 보고서에 반영할 것

이 엔진이 **하지 않는 것**을 알고 써야 한다. 사양보다 좁은 부분은 다음과 같다.

| 항목 | 구현 범위 | 보완 방법 |
|---|---|---|
| 트랜치 | **첫 번째 트랜치만** 월별 잔액·이자·상환을 모델링한다. `00_입력`에는 전 트랜치가 표시되고 LTV·LTC는 합계 한도로 계산된다 | 다중 트랜치 구조·상환 우선순위는 `04_finance_plan.md`에 서술로 기재 |
| 금리 민감도 | 별도 표 없음 | `00_입력`의 금리 셀을 바꾸면 이자·PF잔액·사업이익이 전부 재계산된다. 정적 표보다 정확하다 |
| 분양률 민감도 | 총액 기준 근사표(100/90/80/70%) | 회수 시점 변화는 `schedule.분양률` 배열을 수정해 재생성 |
| IRR | 미산출 | 필요 시 `02_현금흐름`의 월 순현금 행에 Excel `IRR()` 직접 적용 |
| 정비사업 조합원분양분 | `revenue`에 넣으면 일반분양과 같은 분양률 곡선으로 유입된다. 실제로는 조합원 분담금 납부 스케줄이 달라 회수 시점이 다르다 | `분양률` 배열은 일반분양 기준으로 잡고, 시점 차이를 보고서에 명시 |
| 준공 전/후 적립비율 | 준공 시점(인허가+공사 개월) 기준으로 자동 전환 | — |
| 사업기간 상한 | 180개월. 초과 시 경고 후 절단 | 초과 사업은 구간을 나누어 검토 |

## 주의

- 텍스트 항목이 `=`로 시작하면 Excel이 수식으로 오인한다 → 엔진이 자동으로 공백을 붙여 방어한다. 그래도 `산출근거`에 `=`로 시작하는 문자열은 피한다
- 시트명이 숫자로 시작하므로 수식의 시트 참조는 **항상 작은따옴표**로 감싼다: `='01_사업수지'!E32`
- 금액 단위는 **천원**으로 통일한다. 원 단위와 섞으면 검증이 무의미해진다
- 조합원 개인정보(실명·주소·연락처)는 어떤 시트에도 넣지 않는다 (헌법 5조)
