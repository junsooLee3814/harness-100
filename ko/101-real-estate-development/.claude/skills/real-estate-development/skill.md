# Real Estate Development — 부동산개발 사업계획 파이프라인

정비사업 조합 시행과 민간 자체시행 두 트랙에 대해, 인허가 절차부터 사업수지·자금조달·세무·리스크까지 사업계획서를 체계적으로 생성한다.

## 실행 모드

**에이전트 팀** — 6명이 SendMessage로 직접 통신하며 교차 검증한다.

## 에이전트 구성

| 에이전트 | 파일 | 역할 | 타입 |
|---------|------|------|------|
| permit-navigator | `.claude/agents/permit-navigator.md` | 절차·법정기한·동의율·인허가 리스크 | general-purpose |
| sales-analyst | `.claude/agents/sales-analyst.md` | 분양가·경쟁단지·분양률 시나리오 | general-purpose |
| feasibility-analyst | `.claude/agents/feasibility-analyst.md` | 사업수지·비례율·손익분기·엑셀 | general-purpose |

## 워크플로우

### Phase 1: 준비 (오케스트레이터 직접 수행)

1. 사용자 입력에서 **필수 9변수**를 추출한다. 3개 층으로 나뉘며, **①층은 하나라도 빠지면 진행할 수 없다.**

    **① 좌표 (3) — 판단의 전제. 없으면 계산해도 의미가 없다**

    | # | 변수 | 없으면 무너지는 것 |
    |:-:|---|---|
    | 1 | **소재지** (시·군·구, 가능하면 읍면동) | 분양가상한제·HUG 고분양가 관리지역 판정 불가 → **헌법 1조 적용 불가**. 부담금 5종이 전부 조례 위임이라 세무 검토 불가. 지역별 초기분양률 실적을 못 붙이므로 분양률 가정의 근거가 사라짐 → 낙관편향 차단 실패 |
    | 2 | **사업 유형** (정비사업 재개발·재건축 / 민간 자체시행) | 트랙 분기 불가. 비례율·재초환 적용 여부가 갈린다 |
    | 3 | **현재 단계** (토지매입 전 / 구역지정 / 조합설립 / 사업시행인가 / 관리처분 / 착공 / 준공 / 청산) | 절차 시작점·잔여 기간 산정 불가 |

    **② 규모 (3) — 매출과 최대 비용을 만드는 값**

    | # | 변수 | 비고 |
    |:-:|---|---|
    | 4 | **분양면적(평)** — 용도별 | 직접 모르면 `대지면적 × 용적률 × 전용률`로 도출한다. 대지면적만으로는 부족하다 |
    | 5 | **평당 분양가** — 용도별 | 소재지가 있어야 타당성을 검증할 수 있다. 검증 없는 분양가는 낙관 편향의 출발점 |
    | 6 | **평당 공사비** (+ 연면적) | 최대 비용 항목. `[가정]`이면 민감도 ±20% 필수 |

    **③ 자금·시간 (3)**

    | # | 변수 | 비고 |
    |:-:|---|---|
    | 7 | **토지매입비** | 정비사업은 대신 **현금청산금·국공유지 매입비·주거이전비** (조합원 토지는 현물출자이므로 매입비가 없다) |
    | 8 | **사업기간** (인허가 / 공사 / 분양정산 + **지연 버퍼**) | 기간이 곧 금융비용 |
    | 9 | **조달금리** | 브릿지·본PF를 분리해 받는다 |

    - **권장** (없으면 오차가 커짐): 자기자본 · PF 한도 · 세대수·평형 구성 · 지하주차 규모 · 분양 개시 시점·목표 분양률
    - **참고정보** (수지에 반영되지 않음): 건폐율 · 주차대수 — 배치·층수 판단용이며 사업수지 계산에는 쓰이지 않는다
    - **정비사업 추가 3변수**: 종전자산 평가액 총액 / 조합원 수 / **조합원 분양가**
        - 분담금 = 조합원 분양가 − 권리가액 이므로 조합원 분양가가 필요하다
        - **총사업비는 입력받지 않는다.** 하네스가 지출 4대 분류를 합산해 산출한다.
          이미 확정된 총사업비가 있어 검산만 원하는 경우에만 참고값으로 받는다
    - **기존 자료** (선택): 가설계 면적표, 감정평가서, 사업수지 초안, 대주 텀시트

2. **입력값의 출처와 검증 원칙 ★ 이 하네스의 기본 자세**

    **필요한 모든 정보는 사업주(사용자)가 제시한다. 하네스는 값을 만들어내지 않고, 제시된 값이 인근 시세·최근 실적·법정 기준에 부합하는지 판정한다.**

    | 값 | 제시 주체 | 하네스의 역할 |
    |---|---|---|
    | 평당 분양가 | 사업주 | 인근 실거래·최근 분양 실적과 대조 → `부합 / 낙관 / 보수` 판정 (sales-analyst) |
    | 평당 공사비 | 사업주 | 용도·규모별 최근 시공 실적·공사비지수와 대조 → 판정. 물가상승 반영 여부 점검 (feasibility-analyst) |
    | 토지매입비 | 사업주 | 인근 토지 실거래·공시지가와 대조 → 판정 |
    | 조달금리·한도 | 사업주 | 텀시트 유무 확인. 없으면 시장 일반 수준과 대조 |
    | 사업기간 | 사업주 | 절차별 표준 소요기간과 대조 → 과소 설정 여부 판정 (permit-navigator) |

    - **판정이 `낙관`이면 사업주에게 알리고 보수 시나리오를 병기**한다. 제시값을 조용히 채택하지 않는다
    - 사업주가 근거를 대며 유지를 원하면 그 결정을 따르되, **판정 결과와 사유를 보고서에 남긴다**
    - 시장 데이터 조회 실패 시 "검증 불가 — 시장데이터 미조회"로 표기한다. 검증되지 않은 값을 검증된 것처럼 쓰지 않는다
    - 사업주가 값을 갖고 있지 않은 경우에 한해 하네스가 **범위를 제안**하고 확정을 요청한다. 단독 확정 금지

3. **누락 시 처리 — 층에 따라 다르게 대응한다.**
    - **①층(좌표) 1개라도 누락 → 즉시 질의. 다른 작업을 시작하지 않는다.** 소재지 없이 대지면적만 받아 계산을 시작하면, 검증되지 않은 분양가를 그대로 삼켜 낙관 편향 산출물을 만든다
    - **②③층 3개 이상 누락 → 작업 중단 후 질의.** 임의 추정으로 채우지 않는다
    - **②③층 1~2개 누락 → `[가정]` 태그 + 근거 명시**, 가정 목록 표에 등재, 민감도에서 범위 검토
3. `_workspace/` 디렉토리를 프로젝트 루트에 생성한다
4. 입력을 정리하여 `_workspace/00_input.md`에 저장한다 — 미제공 항목은 `[미제공]`으로 명시
5. 요청 범위에 따라 **실행 모드를 결정**한다

### Phase 2: 팀 구성 및 실행

| 순서 | 작업 | 담당 | 의존 | 산출물 |
|:-:|------|------|------|--------|
| 1a | 인허가·절차 | permit-navigator | 없음 | `_workspace/01_permit_schedule.md` |
| 1b | 분양성 | sales-analyst | 없음 | `_workspace/02_sales_analysis.md` |
| 2 | 사업수지 | feasibility-analyst | 1a, 1b | `_workspace/03_feasibility.md` + xlsx |
| 3a | 자금조달 | finance-architect | 2 | `_workspace/04_finance_plan.md` |
| 3b | 세무·부담금 | tax-accountant | 2 | `_workspace/05_tax_review.md` |
| 4 | 리스크·사업계획서 | risk-reporter | 전부 | `_workspace/06_business_plan.md` |

작업 **1a·1b는 병렬**, **3a·3b도 병렬** 실행한다.

**★ 필수 왕복 2건 (생략 금지)**
- feasibility-analyst → finance-architect → **금융비용 회신** → 사업수지 재반영
- feasibility-analyst → tax-accountant → **부담금·세액 회신** → 사업수지 재반영

이 왕복 없이 진행하면 금융비용·부담금이 빠진 수지가 되어 사업이익이 과대계상된다.

**팀원 간 소통 흐름:**
- 1a·1b 병렬 완료 → feasibility에게 사업기간·마일스톤 + 분양가·분양률 곡선 전달
- feasibility 완료 → finance에게 총사업비·자금집행 구분, tax에게 사업이익·취득가액 전달
- finance → feasibility에게 금융비용 회신 / tax → feasibility에게 부담금·세액 회신
- feasibility가 재계산하여 최종 수지 확정 → 엑셀 재생성
- 전원 완료 → risk-reporter가 교차 검증 후 최종 사업계획서 작성

### Phase 3: 통합 및 최종 산출물

1. `_workspace/` 내 모든 파일을 확인한다
2. 교차 검증:
    - [ ] 분양수입이 분양성분석과 사업수지에서 일치하는가
    - [ ] 사업기간이 인허가분석과 금융비용 계산에서 일치하는가
    - [ ] 금융비용이 자금조달 계획과 사업수지에서 일치하는가
    - [ ] 부담금·세액이 세무검토와 사업수지에서 일치하는가
    - [ ] 분양률 곡선이 분양성분석과 현금흐름에서 일치하는가
    - [ ] 엑셀 `#REF!` 0건, 균형식 FALSE 0건인가
    - [ ] 조합원 실명·주소 노출 0건인가 (헌법 5조)
    - [ ] 낙관편향 감사 7항목이 모두 준수되었는가 (차단 규칙 5종 + 재초환·부담금 2항목)
3. 불일치 발견 시 해당 에이전트에게 수정 요청 (최대 2회)
4. 최종 요약을 사용자에게 보고한다

## 헌법 (타협 불가 5조)

1. 분양가상한제 적용지역은 분양가 임의 산정 금지 — 택지비+기본형건축비+가산비 구조로만
2. 재건축 수지에서 재초환 예정액 미반영 금지 — 불가 시 "이익 과대 가능" 경고 필수
3. 비례율·분담금은 "가평가(참고치)" 표기 — 법정 감정평가 대체 금지
4. PF 자기자본비율 등 시행 예정 규제는 시행 시점 명시 — 현행 확정 규제로 서술 금지
5. 조합원 개인정보(실명·주소·연락처) 노출 금지 — 익명 ID만

## 테스트 시나리오

### 정상 흐름
**프롬프트**: "경기도 ○○시 대지 5,000㎡, 용적률 250%, 아파트 120세대 개발 검토 중이야. 토지비 200억, 평당 공사비 650만원, 예상 분양가 평당 1,800만원. 사업계획서 만들어줘"
**기대 결과**:
- 인허가: 주택법 사업계획승인(30세대↑) 대상, 지구단위·건축심의 일정, 총 사업기간 산정
- 분양성: 인근 분양 실적 검색, 분양가 근거 제시, 분양률 3시나리오
- 사업수지: 4대 분류 지출, 사업이익률, 손익분기 분양률, 엑셀 6시트
- 자금조달: 브릿지→본PF, 트랜치, 피크자금, 워터폴
- 세무: 부담금 5종 전수 점검, 취득세, VAT 과세·면세 구분
- 리스크: 매트릭스 + 조기경보지표, 낙관편향 감사 7항목, 교차검증

### 정비사업 흐름
**프롬프트**: "재건축조합인데 종전자산 총액 3,000억, 조합원 500명, 조합원 분양가 평균 8.5억, 일반분양 포함 종후자산 6,500억 예상. 비례율이랑 분담금 추산해줘"
**기대 결과**:
- 정비 수지 모드로 전환, 비례율 = (종후 − 총사업비) ÷ 종전
- **"가평가(참고치)" 표기 필수**, 재초환 반영, 공사비 ±20% 비례율 민감도
- 조합원 익명 ID 사용

### 에러 흐름
**프롬프트**: "이 땅 사업성 있을까?"
**기대 결과**:
- 필수 변수 대부분 누락 → 작업 중단 후 9변수 질의
- 최소 정보로 일반론 제시하되 "산정 불가" 명시
- 임의 추정 금지
